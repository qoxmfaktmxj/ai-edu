업무로 가져가기

1회차의 프롬프트와 컨텍스트를 개발 업무로 확장합니다. 저장 오류 예제로 실행과 검증 환경을 만드는 하네스 엔지니어링을 이해하고, 사이트를 만들며 쓴 흐름을 실제 업무에 옮깁니다.

요청에서 작업 환경으로

1회차에서는 부탁에 목적과 자료를 더했습니다. 개발에서는 코드와 오류 로그가 컨텍스트가 됩니다. 여기에 실행 도구와 테스트를 연결하면 AI가 자기 변경을 직접 확인할 수 있습니다.

개념설계하는 것메모 앱의 저장 오류 예
프롬프트 엔지니어링요청과 완료 기준빈 제목은 저장하지 않고 오류 문구를 보여 달라고 요청
컨텍스트 엔지니어링필요한 정보를 찾고 참고하게 하는 방법저장 처리 코드, 재현 순서, 업무 규칙과 로그를 연결
하네스 엔지니어링AI가 작업하고 결과를 확인하며 다시 고칠 수 있는 실행 체계개발 앱 실행, 테스트, 브라우저 확인, 실패 결과 전달과 권한 범위 구성

세 가지는 함께 씁니다. 하네스 엔지니어링에서는 프롬프트와 자료에 더해 도구, 실행 환경, 검증 절차와 권한을 갖춥니다. 규칙을 파일에 적는 것도 일부지만, "테스트해 줘"라고 써 두는 것만으로 테스트가 실행되지는 않습니다.

저장 버튼 오류를 세 단계로 다루기

다음은 교육용 가상 메모 앱 사례입니다. 빈 제목으로 저장하면 오류 안내 없이 저장되는 문제가 있다고 가정합니다. 실제 연습에서는 직접 만든 앱이나 공개 연습 저장소의 파일과 명령으로 바꿉니다.

  1. 원하는 동작을 구체적으로 요청합니다

    "저장 버튼 고쳐 줘" 대신 "제목이 비어 있거나 공백뿐이면 저장하지 말고 '제목을 입력해 주세요'를 보여 줘. 정상 제목은 기존처럼 한 번 저장돼야 해"라고 말합니다. 무엇을 고칠지와 성공 기준이 생깁니다.

  2. 관련 자료를 찾게 합니다

    "메모 작성 화면에서 제목을 비우고 저장을 누르면 빈 제목이 저장된다"는 재현 순서와 오류 로그를 줍니다. AI가 화면의 저장 처리, 저장 API, 관련 테스트를 찾아 읽고 원인을 설명하게 합니다. 관련 없는 코드 전체를 무조건 넣기보다 필요한 위치와 최신 규칙을 찾을 수 있게 합니다.

  3. 실행하고 실패 결과로 다시 고치게 합니다

    개발 앱을 띄울 방법, 가상 데이터, 테스트 명령과 브라우저 도구를 준비합니다. 빈 제목, 공백뿐인 제목, 정상 제목을 확인하고 실패 결과를 다시 작업에 반영합니다. 운영 DB와 배포 권한은 연결하지 않습니다. 필요한 도구나 환경이 없으면 무엇을 확인하지 못했는지 보고하게 합니다.

요청과 자료 확인 → 수정 → 테스트와 화면 확인 → 실패 원인 확인 → 다시 수정하는 과정을 실제로 돌릴 수 있게 만드는 것이 이 예제의 하네스입니다. 테스트가 통과해도 요구사항과 변경 범위에 대한 사람의 검토는 남습니다.

우리 프로젝트에서 갖출 것

준비할 것저장 오류 예에서의 역할
짧은 프로젝트 규칙과 문서 위치저장 규칙, 관련 코드와 테스트 위치를 찾게 함
다시 실행할 수 있는 개발 환경실행 명령과 가상 데이터로 같은 오류를 재현
필요한 도구와 제한된 권한파일 수정, 개발 명령과 브라우저 확인을 허용하고 운영 변경은 분리
테스트와 확인 가능한 결과성공 여부를 테스트 결과, 저장 건수와 화면으로 판단
검토와 되돌릴 방법diff를 검토하고 작은 커밋으로 변경을 추적

도구 연결에 MCP를 쓸 수 있지만, MCP 연결 자체가 하네스 전체는 아닙니다. 지금 배우는 CLAUDE.md, 실행 명령, 테스트, 미리보기와 Git도 이 작업 환경을 이루는 요소입니다. 프롬프트만 계속 늘리기 전에, AI가 필요한 자료를 읽고 결과를 확인할 수 있는지 봅니다.

회사 코드에 쓰기 전에

승인된 도구와 계정에서만 씁니다
  • 회사 소스, 쿼리, DB, 로그를 외부 AI에 넣어도 되는지는 회사 정책이 정합니다. 오늘 만든 개인 계정에는 넣지 않습니다. 아래 예시는 공개된 오픈소스 저장소나 직접 만든 가상 코드로 먼저 연습합니다.
  • 접속 정보가 든 파일(.env, 운영 설정 파일)은 Claude가 읽지 못하게 작업 폴더에서 빼거나, Claude Code 설정의 deny 규칙으로 막습니다.
  • 회사 저장소에서는 권한 모드를 Manual이나 Accept edits로 두고, 운영 서버나 DB에 닿는 명령은 직접 확인합니다. Bypass permissions는 쓰지 않습니다.
  • 생성된 코드의 책임은 커밋한 사람에게 있습니다. 리뷰하고 테스트가 통과한 뒤에 병합합니다.
