업무로 가져가기

오늘 사이트를 만들며 익힌 "말로 부탁하고, 결과를 확인하고, 구체적으로 고쳐 달라고 하는" 기술을 실제 업무에 옮겨 봅니다. 업무 활용 예시 7가지와 바로 복사해 쓰는 프롬프트, 지켜야 할 보안 수칙을 함께 담았습니다.

약 40분(예시 따라 하기 포함)난이도 쉬움

오늘 배운 진짜 기술

지금까지 여러분은 사이트를 만들었습니다. 그런데 사실 이 교육에서 가장 중요하게 연습한 것은 사이트 만드는 법이 아닙니다. 아래 네 동작의 반복입니다.

  1. 말로 부탁하기
  2. 결과 확인하기
  3. 구체적으로 고쳐 달라고 하기
  4. 다시 확인하기

사이트 만들기는 이 기술을 연습하기 위한 연습 무대였습니다. 무대를 바꾸면 같은 기술이 그대로 업무에 적용됩니다. 아래 표처럼, 이미 해 본 일이 업무의 어떤 장면과 이어지는지 연결해 보세요.

교육에서 해 본 일업무에서는 이렇게 쓰입니다
"첫 화면을 만들어 주세요"라고 부탁"주간 보고 초안을 만들어 주세요"라고 부탁
색이 마음에 안 들어 "더 차분한 색으로 바꿔 주세요"문장이 딱딱해서 "더 부드러운 말투로 바꿔 주세요"
스킬을 설치해서 Claude의 실력 높이기우리 팀의 작성 규칙을 Claude에게 미리 알려 주기
Claude가 "실행해도 될까요?" 하면 읽고 허용AI가 만든 결과와 하려는 일을 내가 검토하고 승인
배포한 주소를 보내 공유만든 결과물과 사용한 프롬프트를 팀에 공유
왜 "확인하기"가 그렇게 중요한가요?

AI는 자신 있는 말투로 틀린 내용을 쓸 때가 있습니다. 숫자가 바뀌거나, 없는 내용이 끼어들거나, 날짜가 어긋나는 식입니다. 결과를 쓰기 전에 사람이 원본과 대조하는 것이 AI 시대의 기본 습관입니다. 이 교육에서 사이트를 직접 열어 눌러 본 것도 같은 연습이었습니다.

좋은 부탁의 공식

AI에게 부탁할 때 아래 다섯 가지를 담으면 결과가 눈에 띄게 좋아집니다. 전부 쓸 필요는 없습니다. 빠뜨린 것이 있으면 Claude가 되물어 오기도 하고, 결과를 본 뒤 "이 부분이 더 필요해요"라고 덧붙여도 됩니다.

요소스스로에게 던질 질문예
1. 목적이 일을 왜 하나요? 무엇에 쓰나요?월요일 팀 회의에서 지난주 일을 3분 안에 공유하려고 합니다
2. 대상, 독자누가 읽거나 쓰나요?바쁜 팀장님. 배경 설명은 필요 없음
3. 결과물 형태어떤 모양으로 받고 싶나요?5줄 요약 하나와 다음 주 할 일 표
4. 조건, 제약꼭 지킬 것, 하지 말 것은?메모에 없는 내용은 지어내지 말 것, 숫자는 그대로
5. 확인 방법잘 됐는지 어떻게 알죠?불확실한 부분은 마지막에 질문으로 모아 달라고 요청

나쁜 부탁과 좋은 부탁 비교

나쁜 부탁

  • "지난주 일 정리해서 보고서 만들어 주세요."
  • 누가 읽는지, 몇 줄이어야 하는지, 형식이 무엇인지 알 수 없습니다.
  • Claude가 빈칸을 추측으로 채우기 때문에 결과가 엉뚱하거나 너무 길어질 수 있습니다.
  • 결과가 맞는지 확인할 방법도 없습니다.

좋은 부탁 추천

  • 목적, 독자, 결과물 형태, 조건, 확인 방법이 모두 들어 있습니다.
  • "지어내지 마세요" 같은 금지 조건이 있어서 엉뚱한 내용이 줄어듭니다.
  • 불확실한 부분을 따로 모아 달라고 해서 내가 확인할 곳이 한눈에 보입니다.
  • 아래 카드가 그 예입니다.

그대로 붙여 넣어 Claude의 채팅 및 Cowork 탭에서 시험해 보세요. 메모는 가짜 예시이니 안심하고 써도 됩니다.

다음 단계는 "고쳐 달라고 하기"입니다

첫 결과가 마음에 들지 않을 때가 오히려 기회입니다. "별로예요, 다시 해 주세요"라고 하면 Claude는 무엇을 고쳐야 할지 알 수 없습니다. 어디가, 왜, 어떻게 마음에 안 드는지 말해 주면 한 번에 좋아집니다.

막연한 수정 요청

  • "별로예요. 다시 써 주세요."
  • "좀 더 좋게 해 주세요."
  • 결과가 완전히 달라져서 좋았던 부분까지 사라질 수 있습니다.

구체적인 수정 요청 추천

  • "두 번째 문단이 너무 길어요. 세 줄로 줄여 주세요."
  • "숫자와 날짜는 그대로 두고, 말투만 부드럽게 바꿔 주세요."
  • 고칠 곳과 그대로 둘 곳을 함께 알려 주는 것이 핵심입니다.

어떤 결과물에도 쓸 수 있는 "고쳐 달라고 하기" 틀입니다. 대괄호 안을 내 상황에 맞게 바꿔 쓰세요.

업무 활용 예시 7가지

아래 예시는 모두 가짜 예시 데이터로 바로 시험해 볼 수 있게 만들었습니다. 따라 해 보고, 잘 되면 그때 내 업무에 맞게 바꿔 보세요.

모든 예시의 공통 원칙: 실제 고객 정보와 기밀은 넣지 않고, 가짜 예시 데이터로 먼저 해 봅니다

이 장의 프롬프트는 모두 가짜 데이터나 자리 표시로 연습하도록 되어 있습니다. 이렇게 하면 세 가지가 좋습니다.

  • 보안 수칙을 어길 걱정이 없습니다.
  • 가짜 데이터는 정답을 내가 알 수 있어서 AI가 제대로 했는지 검산하기 쉽습니다.
  • 망쳐도 잃을 것이 없으니 마음껏 고쳐 달라고 해 볼 수 있습니다.

어디서 하나요? 채팅 및 Cowork 탭과 Code 탭

채팅 및 Cowork 탭

  • 일반 대화는 내 PC 파일에 접근하지 않습니다. Cowork는 내가 허용한 파일에 접근할 수 있지만 이 교육에서는 일반 대화만 씁니다.
  • 글 요약, 이메일 초안, 아이디어 정리처럼 글만 주고받는 일에 씁니다.
  • 필요한 글은 직접 붙여 넣습니다. 이때도 가짜 예시만 붙여 넣으세요.

Code 탭 파일이 필요할 때

  • 내 PC의 폴더를 골라 그 안에서 파일을 만들고 고치는 곳입니다.
  • CSV 정리, HTML 대시보드, 계산기, 파일 정리 스크립트처럼 결과 파일이 생기는 일에 씁니다.
  • 폴더는 반드시 연습 전용 빈 폴더를 고르세요.
Code 탭에서는 연습 전용 폴더만 선택하세요

Code 탭의 Claude는 선택한 폴더 안의 파일을 읽고 만들고 고칠 수 있습니다. 그래서 "바탕화면" 전체나 "문서" 폴더 전체를 고르면 안 됩니다. 새로 만든 빈 폴더(예: ai-practice)를 고르세요. 화면 문구는 업데이트로 조금 다를 수 있습니다.

  1. Claude 앱 위쪽 Code 탭
  2. Local 선택
  3. Select folder
  4. 연습 전용 폴더 선택

권한 모드는 2장에서 정한 Accept edits(파일 수정은 자동으로 받아들이고, 명령 실행은 매번 물어보는 방식)를 그대로 씁니다. 모든 질문을 건너뛰는 Bypass permissions는 사용하지 마세요. 예전 버전에서는 이 이름들이 Ask permissions, Auto accept edits 등으로 표시되기도 했습니다.

예시 1. 엑셀/CSV 데이터 정리

날짜 형식이 제각각이거나, 이름 앞뒤에 공백이 있거나, 같은 줄이 중복된 표는 업무에서 정말 자주 만납니다. 이런 정리를 AI에게 맡기는 연습입니다. CSV는 쉼표로 칸을 나눠 적은 단순한 표 파일이고, 엑셀로 열고 저장할 수 있습니다. 아래는 가짜 데이터를 일부러 지저분하게 만든 뒤 정리하는 흐름입니다.

Claude가 파일을 만들고 도구를 실행하기 전에 허락을 구합니다. 무엇을 하려는지 읽고 허용하세요.

성공하면 보이는 모습, 막혔을 때, 실제 업무에 쓰려면
성공하면
폴더에 sample-orders.csv와 sample-orders-clean.csv 두 파일이 생깁니다. 정리본을 엑셀로 열었을 때 한글이 정상으로 보이고, 날짜가 모두 같은 형식이며, 줄 수가 원본보다 중복 개수만큼 줄어 있습니다. Claude의 요약 표와 실제 줄 수가 맞는지 직접 세어 보세요.
한글이 깨지면
"엑셀에서 열었더니 한글이 깨져요. 엑셀이 잘 읽는 UTF-8 BOM 형식으로 다시 저장해 주세요"라고 말하세요. UTF-8 BOM은 엑셀이 한글 파일임을 알아보도록 파일 맨 앞에 붙이는 표식입니다.
도구 오류가 나면
화면에 나온 오류 문구를 복사해서 "이런 오류가 나왔어요. 쉬운 말로 설명하고 해결해 주세요"라고 붙여 넣으세요. 오류 문구에 내 이름이나 폴더 경로가 있으면 가려도 됩니다.
실제 업무 파일이라면
엑셀 파일은 "다른 이름으로 저장"에서 CSV 형식으로 저장하면 Claude가 다루기 쉬워집니다(메뉴 이름은 엑셀 버전에 따라 조금 다릅니다). 다만 실제 데이터는 개인정보나 고객 정보가 있는지 먼저 확인하고, 회사가 승인한 도구와 절차 안에서만 사용하세요.

예시 2. 반복 보고서를 한 장짜리 HTML 대시보드로

매달 같은 숫자를 표와 그래프로 만드는 보고서가 있다면, 숫자만 바꿔 끼우면 되는 한 장짜리 화면으로 만들어 둘 수 있습니다. HTML 파일은 더블클릭하면 브라우저에서 열리는 파일입니다. 이번에는 가상의 카페 매출로 연습합니다.

"숫자를 한곳에 모아 달라"는 조건이 핵심입니다. 나중에 매달 숫자만 바꾸면 같은 보고서를 다시 쓸 수 있습니다.

성공하면 보이는 모습, 막혔을 때, 실제 업무에 쓰려면
성공하면
폴더에 dashboard.html 파일이 생기고, 더블클릭하면 브라우저가 열려 카드, 그래프, 표가 보입니다. 휴대폰 화면 크기로 줄여도(브라우저 창을 좁혀도) 내용이 잘리지 않아야 합니다.
빈 화면이거나 그래프가 안 보이면
"브라우저로 열었더니 그래프가 안 보여요(또는 화면이 하얘요). 원인을 찾아서 고쳐 주세요"라고 말하세요. 무엇이 보이는지 한 줄만 덧붙이면 훨씬 빨리 해결됩니다.
숫자가 의심스러우면
카드의 증감률이나 평균을 직접 계산기로 한 번 계산해 보세요. 이 습관이 AI 결과를 믿고 쓰는 가장 확실한 방법입니다.
실제 업무에 쓰려면
실제 매출 숫자는 회사 내부 정보일 수 있습니다. 승인된 도구에서만 사용하고, 만든 파일은 사내에서 허용한 방법으로만 공유하세요. 인터넷에 공개되는 사이트에는 올리지 마세요.

예시 3. 회의록 요약과 할 일 뽑기

길고 두서없는 회의 메모에서 요약, 결정 사항, 할 일을 뽑아내는 일은 AI가 특히 잘하는 작업입니다. 글만 주고받기 때문에 채팅 및 Cowork 탭에서 해도 충분합니다. 먼저 가짜 메모로 연습하세요.

참석자 이름은 A, B, C처럼 가짜 표시로 바꿔서 연습합니다. 실제 회의록은 승인된 도구에서만 다루세요.

성공하면 보이는 모습, 막혔을 때, 실제 업무에 쓰려면
성공하면
요약 5줄, 결정 사항 목록, 할 일 표, 확인 질문 목록이 순서대로 나옵니다. 담당자나 기한이 메모에 없는 항목은 "미정"으로 표시되어야 합니다. 메모에 없던 담당자나 날짜가 들어 있다면 AI가 지어낸 것이니 "이건 메모에 없는데 어디서 나온 건가요?"라고 물어보세요.
결과가 너무 길면
"요약을 3줄로 줄이고, 할 일 표만 남겨 주세요"처럼 구체적으로 다시 부탁하세요.
실제 업무에 쓰려면
실제 회의록에는 사람 이름, 고객사 정보, 미공개 계획이 들어 있기 쉽습니다. 회사가 승인한 AI 도구가 있다면 그곳에서만 사용하세요.

예시 4. 사내 교육 자료, 매뉴얼 웹페이지

긴 문서를 "누르면 펼쳐지고, 체크하면 줄이 그어지는" 읽기 편한 웹페이지로 바꿔 두면 신입 사원이나 협력 직원에게 안내하기 쉽습니다. 이 교육 사이트도 같은 방식입니다. 여기서는 가짜 내용으로 파일 하나짜리 페이지를 만들어 봅니다.

성공하면 보이는 모습, 막혔을 때, 실제 업무에 쓰려면
성공하면
목차를 누르면 해당 항목으로 이동하고, 질문을 누르면 답이 펼쳐지며, 체크박스를 누르면 글자에 줄이 그어집니다. 휴대폰 크기로 줄여도 글이 읽기 편해야 합니다.
마음에 안 들면
"질문 부분 글자를 더 크게 해 주세요", "색을 파란 계열로 통일해 주세요"처럼 한 번에 하나씩 고쳐 달라고 하세요. 한꺼번에 많이 고치면 어디가 바뀌었는지 놓치기 쉽습니다.
실제 업무에 쓰려면
사내 매뉴얼에는 내부 정보가 들어 있으므로 Vercel 같은 공개 사이트로 배포하면 안 됩니다. 사내 공유는 승인된 문서 시스템이나 파일 전달 방법을 쓰세요. 외부 사람에게 보여 줄 공개 안내문처럼 공개해도 되는 내용만 공개 배포 대상입니다.

예시 5. 간단한 계산기, 체크리스트 도구

"이 값을 넣으면 합계와 한도 초과 여부를 알려 주는" 작은 도구는 엑셀 수식을 모르는 사람도 AI에게 부탁해 만들 수 있습니다. 여기서는 출장비 계산기를 연습합니다. 단가와 한도는 실제 규정이 아니라 내가 임의로 정한 예시 숫자를 씁니다.

[예시 일비 숫자]처럼 대괄호 안을 숫자로 바꿔 넣고, 대괄호 기호는 지웁니다.

성공하면 보이는 모습, 막혔을 때, 실제 업무에 쓰려면
성공하면
숫자를 입력하는 즉시 합계가 바뀌고, 한도를 넘기면 빨간 "한도 초과" 문구가 나타납니다. 직접 계산기로 두세 가지 경우를 계산해 화면과 비교하세요.
합계가 이상하면
"출장 2일, 교통비 50000, 숙박비 80000, 1박일 때 합계가 얼마여야 하는데 화면에는 이렇게 나와요"처럼 입력한 값과 기대한 값, 실제 값을 알려 주세요. Claude가 어느 계산이 틀렸는지 찾습니다.
실제 업무에 쓰려면
실제 회사의 단가표와 한도는 내부 정보일 수 있습니다. 사내에서 쓰는 도구는 회사가 승인한 방식으로 만들고 배포하세요.

예시 6. 반복 파일 작업 자동화 스크립트

파일 이름 규칙 바꾸기, 종류별로 폴더에 나누기처럼 매번 손으로 하던 반복 작업은 스크립트(컴퓨터가 순서대로 실행하는 명령 모음 파일)로 만들 수 있습니다. 파일을 옮기고 이름을 바꾸는 일이라 실수하면 파일이 엉킬 수 있으므로, 이 예시는 안전장치를 꼭 함께 부탁합니다.

"미리보기 먼저, 삭제 금지, 덮어쓰기 금지"가 자동화를 안전하게 쓰는 세 가지 약속입니다. 처음에는 꼭 이 조건을 붙이세요. "확인용 옵션"은 실행 명령 끝에 덧붙이는 짧은 단어로, 정확한 모양은 Claude가 알려 줍니다.

성공하면 보이는 모습, 막혔을 때, 실제 업무에 쓰려면
성공하면
처음 실행: 변경 예정 목록만 나옵니다. 확인용 옵션으로 두 번째 실행: 파일이 문서, 이미지, 기타 폴더로 나뉘고 이름 앞에 날짜가 붙습니다. 같은 이름이 있던 파일은 건너뛰었다는 안내가 나옵니다.
실행이 차단되면
회사 PC의 보안 설정이 스크립트 실행을 막을 수 있습니다. 보안 설정을 억지로 풀거나 우회하지 마세요. 화면의 메시지를 Claude에게 보여 주고 다른 방법이 있는지 묻거나, IT 담당자에게 문의하세요.
삭제하는 동작이 보이면
Claude가 파일을 지우려는 요청을 하면 거절하세요. "삭제는 하지 말라고 했어요. 삭제 없이 다시 만들어 주세요"라고 말하면 됩니다.
실제 업무에 쓰려면
실제 파일 폴더에서 처음 돌릴 때는 반드시 복사본 폴더에서 먼저 시험하세요. 업무 파일 이름에 고객명이나 계약 정보가 들어 있다면 AI에 보여 주지 않도록 주의하세요.

예시 7. 이메일, 공지문 초안 다듬기

이메일이나 공지문은 처음부터 쓰는 것보다 초안을 받아 다듬는 편이 훨씬 빠릅니다. 톤을 달리한 여러 버전을 받아 비교해 보는 것도 AI가 잘하는 일입니다. 글만 주고받으므로 채팅 및 Cowork 탭에서 합니다.

상황 칸에는 실제 사건의 고객 이름이나 연락처 대신 가짜 또는 일반적인 표현을 쓰세요.

성공하면 보이는 모습, 막혔을 때, 실제 업무에 쓰려면
성공하면
두 가지 톤의 본문과 제목 후보 3개가 나오고, 마지막에 "점심 제공 여부", "참석 필수 여부" 같은 확인 질문이 정리되어 있습니다. 내가 준 날짜, 시간, 장소가 본문과 정확히 일치하는지 보세요.
톤이 마음에 안 들면
"두 번째 버전에서 마지막 문장만 좀 더 부드럽게 바꿔 주세요", "존댓말은 유지하고 너무 딱딱한 표현만 풀어 주세요"처럼 고칠 곳을 짚어서 다시 부탁하세요.
보내기 전에
메일의 실제 발송은 반드시 내가 직접 합니다. 받는 사람, 날짜, 첨부 파일을 한 번 더 확인하세요. 실제 이름과 연락처를 자리 표시에서 내 손으로 채워 넣는 것도 내 몫입니다.

보안 수칙 다시 한 번

업무에 가져가는 순간부터는 보안이 가장 중요한 주제입니다. 1장에서 본 내용을 다시 강조합니다.

사내 데이터는 회사가 승인한 도구에서만 사용합니다
  • 실제 업무 자료(고객 정보, 직원 정보, 미공개 재무 정보, 계약서, 대외비 문서)는 회사가 사용을 승인한 AI 도구와 절차 안에서만 다룹니다.
  • 이 교육에서 만든 개인 계정(Claude, GitHub, Vercel)에는 실제 업무 자료를 넣지 않습니다. 연습용 가짜 데이터만 사용합니다.
  • 어떤 AI 도구가 승인되어 있는지 모르면 정보보안팀이나 IT 담당자에게 먼저 물어보세요. 모르는 상태에서 넣는 것보다 물어보는 편이 항상 안전합니다.
  • 개인정보, 인증정보(비밀번호, API 키, 토큰, 인증서), 회사 기밀은 어떤 형태로도(입력, 파일 첨부, 스크린샷) 넣지 않습니다.
업무 관련 결과물을 인터넷에 공개 배포하지 않습니다

Vercel에 올린 사이트는 주소를 아는 누구나 볼 수 있습니다. 사내 매뉴얼, 내부 대시보드, 업무 계산기처럼 내부 정보가 담긴 결과물은 Vercel 같은 공개 사이트에 올리지 마세요. 사내 공유는 회사가 허용한 방법(사내 문서 시스템, 사내 메신저, 메일 첨부 등)으로 합니다.

프롬프트를 보내기 전 6가지 점검

업무 관련 내용을 AI에게 보내기 전에 아래 여섯 줄을 한 번 훑어보세요. 습관이 되면 10초면 끝납니다.

다음 단계: 이렇게 이어가세요

교육이 끝났을 때가 오히려 시작입니다. AI가 친숙해지려면 꾸준히 조금씩 써 보는 것이 가장 좋습니다. 네 가지만 기억하세요.

  1. 매주 작은 일 하나를 맡겨 보기

    일주일에 한 번, 15분 안에 끝날 만한 작은 일 하나를 AI에게 맡겨 보세요. 맡기기 좋은 일의 기준은 세 가지입니다. 작고, 반복되고, 틀려도 영향이 적은 일입니다. 어떤 일이 좋을지 모르겠다면 AI에게 먼저 물어보세요.

    질문에 답할 때도 "어떤 일을 하는지"만 말하고 고객 이름이나 내부 숫자는 말하지 않습니다.

  2. 잘 된 프롬프트를 모아 두기

    마음에 드는 결과가 나왔다면 그때의 프롬프트를 바로 저장해 두세요. 다음에 같은 일을 할 때 복사해서 숫자나 내용만 바꾸면 됩니다. 이 자료 맨 아래 부록 A "프롬프트 모음"에도 지금까지 본 모든 프롬프트가 모여 있습니다. 내 것은 아래 표처럼 정리하면 편합니다.

    제목언제 쓰나프롬프트(대괄호로 바뀔 부분 표시)결과 평가 (1~5)고친 점
    주간 보고 5줄 요약월요일 회의 전목적: ... 독자: ... 결과물: ... 조건: ... 확인: ...4"-했습니다" 어미 조건을 추가해서 좋아짐

    보관 장소는 개인 메모 앱이나 회사가 허용한 문서 도구가 좋습니다. 프롬프트 안에는 고객 이름이나 내부 숫자 같은 실제 정보를 넣지 말고, 항상 [대괄호] 자리 표시로 남겨 두세요.

  3. 팀에 공유하기

    혼자만 잘 쓰면 한계가 있습니다. 내가 해 본 일 하나를 5분 정도로 팀에 소개해 보세요. 전과 후의 시간 차이, 사용한 프롬프트, 조심할 점(보안 수칙)을 함께 보여 주면 동료들이 부담 없이 따라 할 수 있습니다. 동료에게 이 교육 자료의 1장 보안 수칙도 함께 알려 주세요.

  4. 이 사이트를 계속 발전시키기

    오늘 만든 사이트는 완성이 아니라 출발점입니다. 새 장면을 하나 더 붙이거나, 다른 분위기의 테마를 만들거나, 모바일에서 더 보기 좋게 다듬어 보세요. "고쳐 달라고 하기"를 계속 연습하는 가장 즐거운 방법입니다. 같은 구조로 다른 소재의 사이트를 새로 만들어 보는 것도 좋습니다.

    "제가 말하기 전에는 올리지 마세요"를 붙이면, 확인하지 못한 변경이 공개되는 일을 막을 수 있습니다. 공개 사이트에는 업무 정보를 넣지 않는다는 점도 잊지 마세요.

자주 묻는 질문

AI가 자신 있게 틀린 말을 하면 어떡하나요?

실제로 그럴 수 있습니다. 숫자, 날짜, 사람 이름, 법이나 규정처럼 틀리면 곤란한 내용은 반드시 원본과 대조하세요. "근거가 된 부분을 알려 주세요", "확실하지 않은 내용은 표시해 주세요"라고 부탁하면 확인할 곳을 줄일 수 있습니다. AI의 결과를 최종 확인하고 책임지는 것은 사람입니다.

같은 부탁을 해도 결과가 매번 달라요.

정상입니다. AI는 매번 새로 생각해서 답하기 때문에 표현이나 구성이 조금씩 다릅니다. 마음에 드는 결과가 나오면 바로 저장하고, 그때의 프롬프트도 함께 보관하세요. 결과를 더 일정하게 하고 싶다면 조건을 구체적으로 적으세요(예: 5줄 이내, 표로, 말투는 "-했습니다").

회사에서 AI 사용이 제한되어 있어요. 어떻게 하나요?

회사의 AI 사용 지침과 승인된 도구가 무엇인지 정보보안팀이나 IT 담당자에게 먼저 확인하세요. 승인되지 않은 도구에는 업무 자료를 넣으면 안 됩니다. 그런 경우에도 가짜 예시 데이터로 연습하는 것은 좋은 준비입니다. 연습으로 익힌 "부탁하고 고치는 감각"은 나중에 승인된 도구를 쓰게 될 때 그대로 쓸 수 있습니다.

코딩을 모르는데, AI가 만든 파일이나 스크립트가 안전한지 어떻게 알죠?

완벽하게 판단하지 못해도 괜찮습니다. 아래 습관만 지키면 위험이 크게 줄어듭니다.

  • 실행하기 전에 "이게 무슨 일을 하는지 쉬운 말로 설명해 주세요"라고 묻습니다.
  • "파일을 삭제하거나, 인터넷으로 데이터를 보내거나, 새 프로그램을 설치하는 내용이 있나요?"라고 직접 물어봅니다.
  • 처음에는 연습 전용 폴더와 가짜 파일로만 시험합니다.
  • 이해가 안 되는데 위험해 보이는 동작은 허용하지 않고 거절합니다.
Code 탭에서 어떤 폴더를 고르면 되나요?

연습할 때마다 새로 만든 빈 폴더를 고르세요. Code 탭에서 환경을 Local로 두고 Select folder를 눌러 폴더를 선택합니다. 바탕화면이나 문서 폴더 전체처럼 중요한 파일이 많은 폴더는 고르지 마세요. 화면 문구는 업데이트로 조금 다를 수 있습니다.

10장을 마치며 확인할 것
  • "부탁하고, 확인하고, 구체적으로 고쳐 달라고 하기"가 이 교육의 핵심 기술이라는 점을 기억합니다.
  • 좋은 부탁의 5요소(목적, 독자, 결과물 형태, 조건, 확인 방법)를 말할 수 있습니다.
  • 업무 예시 중 하나 이상을 가짜 데이터로 직접 따라 해 봤습니다.
  • 사내 데이터는 승인된 도구에서만 쓰고, 업무 결과물은 공개 배포하지 않는다는 점을 알고 있습니다.
  • 이번 주에 AI에게 맡겨 볼 작은 일 하나를 정했습니다.

수고하셨습니다. 이제 AI는 낯선 기술이 아니라 내가 부탁하고 고쳐 가며 함께 일하는 도구입니다. 다음 주에 작은 일 하나부터 시작해 보세요.
