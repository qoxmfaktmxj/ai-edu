04

디자인, 모션 스킬 설치

Claude에게 "디자인 전문가의 작업 설명서"와 "영상 제작 도구"를 붙입니다. 설치도 Claude에게 말로 부탁하면 한 번에 끝납니다.

지금까지 Claude 앱, Claude Code, GitHub, Vercel을 준비했습니다. 이제 Claude가 "디자인을 잘하고, 움직이는 화면과 영상을 만들 줄 아는" 상태로 만들어 봅니다. 새 프로그램을 여러 개 배우는 것이 아닙니다. 이 장에서 여러분이 하는 일은 딱 세 가지입니다.

  • Claude에게 설치를 부탁합니다. 아래 프롬프트 하나를 붙여넣으면 됩니다.
  • Claude가 허락을 구하면 읽고 허용합니다. 무엇을 보고 판단하는지 이 장에서 연습합니다.
  • 새 세션을 열어서 목록에 보이는지 확인합니다.

스킬이 무엇인가요

스킬(Skill)은 Claude에게 붙이는 "전문가의 작업 설명서"입니다. 요리에 비유하면 레시피 카드 한 장입니다. 카드에는 "디자인을 맡으면 먼저 이것을 묻고, 이런 순서로 만들고, 이런 모양은 피하세요" 같은 내용이 글로 적혀 있습니다. Claude는 일을 시작할 때 해당 카드를 읽고 그 기준대로 움직입니다. 같은 부탁이라도 카드가 있으면 결과가 더 일정하고 구체적으로 나옵니다.

카드 한 장만 들어 있는 것도 있고, 카드와 함께 작은 도구(검색 프로그램 등)가 딸려 있는 것도 있습니다. 그래서 어디서 받은 스킬인지가 중요합니다. 이 내용은 아래 "허락 창에서 무엇을 확인하나요"에서 다시 다룹니다.

스킬과 플러그인은 무엇이 다른가요

스킬 (설명서 한 장)

  • 작업 설명서 하나입니다.
  • 부르는 이름은 /스킬이름 입니다. 예: /impeccable
  • GitHub 저장소에서 바로 내려받아 설치합니다. 이번 4가지 중 design-taste-frontend와 impeccable이 이 방식입니다.

플러그인 (꾸러미)

  • 스킬 여러 개와 부속품을 한 상자에 묶은 것입니다.
  • 부르는 이름은 /플러그인명:스킬명 입니다. 예: /ui-ux-pro-max:ui-ux-pro-max, /hyperframes:hyperframes
  • 카탈로그(마켓플레이스)를 먼저 등록하고 그 안에서 설치합니다. 이번 4가지 중 ui-ux-pro-max와 hyperframes가 이 방식입니다.
마켓플레이스(Marketplace)

플러그인 목록이 적힌 카탈로그입니다. 앱스토어와 비슷하지만 GitHub 저장소 하나가 카탈로그 역할을 하기도 합니다. 설치는 두 단계입니다. 먼저 "이 카탈로그를 등록"하고, 그다음 "카탈로그 안의 이 플러그인을 설치"합니다. 설치할 때 이름은 플러그인명@마켓플레이스명 모양으로 적습니다.

왜 하나가 아니라 4가지인가요?

방향 잡기(design-taste-frontend), 완성도 점검(impeccable), 색과 글꼴 자료(ui-ux-pro-max), 영상 제작(hyperframes)이 서로 다른 일이기 때문입니다. 한 번에 다 넣어 두면 6장 이후에 "필요할 때 이름만 부르면" 됩니다.

시작하기 전에 확인할 것

  • Claude 앱의 Code 탭이 열려 있고 Claude가 대답하는 상태여야 합니다. 2장에서 한 설치가 되어 있어야 합니다.
  • 인터넷 연결이 되어 있어야 합니다. 설치는 GitHub에서 파일을 내려받는 일입니다.
  • Node.js가 있으면 편합니다. 스킬 설치 도구 npx는 Node.js와 함께 들어 있습니다. 없다고 나오면 이 장 끝의 "막히면 Claude에게 그대로 전달하세요"를 따라 하세요. Claude에게 설치를 부탁할 수 있습니다.
  • 어느 폴더에서 열어도 됩니다. 이번 설치는 "내 PC 사용자 전체(전역)"에 하므로 작업 폴더와 상관없이 모든 프로젝트에서 쓸 수 있습니다.
  • 회사 PC에서 외부 프로그램 설치가 제한되어 있으면 먼저 IT 담당자에게 확인하세요.
  • 대화 도중에는 모델을 바꾸지 마세요. 캐시된 대화를 Claude가 처음부터 다시 읽어 한도가 더 소모됩니다(2장 참고). 바꾸고 싶다면 새 세션을 시작할 때 고르세요.

Claude의 마지막 보고를 읽습니다

설치 끝, 반드시 새 세션을 시작하세요

설치를 마쳤다고 지금 열려 있는 대화에서 바로 보이지는 않을 수 있습니다. 이미 열린 대화는 시작할 때의 "쓸 수 있는 스킬 목록"을 그대로 쓰는 경우가 있기 때문입니다. 가장 확실한 방법은 새 세션을 여는 것입니다.

데스크톱 앱 추천

  • 왼쪽 사이드바의 + New session 버튼을 누릅니다.
  • 또는 Ctrl+N (Mac은 Cmd+N)을 누릅니다.
  • 빈 대화 화면이 나오면 성공입니다. 이전 세션은 사이드바에 그대로 남아 있습니다.

터미널의 Claude Code

  • 대화창에 /exit 를 입력해 Claude Code를 종료합니다.
  • 같은 터미널에서 claude 를 다시 실행합니다.
  • 처음 화면이 다시 나오면 성공입니다.
새 세션이 번거로울 때의 지름길

플러그인(ui-ux-pro-max, hyperframes)은 현재 세션에서 /reload-plugins 를, 스킬(design-taste-frontend, impeccable)은 /reload-skills 를 입력해 바로 불러올 수도 있습니다. 다만 4가지가 모두 보이는지 확실하게 확인하려면 새 세션이 가장 안전합니다.

제대로 설치됐는지 확인하기

Claude에게 물어봅니다

스킬 부르는 법: 한 줄씩 해 보기

1. 디자인 방향 잡기

2. 만든 화면 비평받기

3. 색과 글꼴 고르기

4. 영상 만들 준비 상담

더 알아보기: REA로 프로그램 뜯어보기 (선택)

스킬과 같은 방법, 즉 GitHub 저장소 이름을 Claude에게 주고 설치를 맡기는 방법으로 넣을 수 있는 도구를 하나 더 소개합니다. REA(Reverse Engineer Anything)는 Claude가 소스 코드 없이 프로그램 내부를 들여다볼 수 있게 분석 도구를 연결해 줍니다. 2026년 10월 일주일 만에 GitHub 별 10만 개를 넘기며 화제가 됐습니다. 수업 필수 과정은 아니고, 개발자 관점에서 "이런 것도 된다"를 직접 확인해 보는 선택 과정입니다.

MCP (Model Context Protocol)

Claude가 바깥 프로그램을 도구처럼 부를 수 있게 이어 주는 연결 규격입니다. 스킬이 "작업 설명서"라면 MCP는 "손에 쥐여 주는 공구"입니다. REA는 스킬이 아니라 MCP 서버라서, 설치하면 Claude가 Ghidra 같은 분석 프로그램을 직접 부릅니다.

어떻게 동작하나요

  1. 내가 Claude에게 "이 프로그램의 이 기능이 어떻게 동작하는지" 묻습니다.
  2. Claude가 REA를 통해 분석 도구를 부릅니다. 윈도우 프로그램은 Ghidra(미국 국가안보국이 만들어 2019년 공개한 무료 도구), 웹사이트는 Chrome, 안드로이드 앱은 JADX 같은 식입니다.
  3. REA가 의사코드(사람이 읽기 쉽게 풀어 쓴 코드), 근거(파일 위치, 함수, 문자열), 모르는 부분을 돌려줍니다. 결과마다 관찰(직접 확인), 추론, 미확인이 구분되어 붙습니다.
  4. Claude가 그 근거로 설명하거나, 내 프로젝트에 비슷한 기능을 새로 만들고 시험합니다.

새로운 분석 기술은 아닙니다. 원래 전문가가 쓰던 도구를 Claude가 대신 쓰게 해 준 것입니다. 국내 분석 글은 REA를 이렇게 평가합니다. "REA의 가치는 '정답을 준다'가 아니라 '틀렸을 때 어디서 틀렸는지 추적할 수 있다'에 가깝습니다."

개발자가 써 볼 만한 곳

상황쓰는 법
설명 문서가 없는 오래된 모듈입력과 출력 규칙, 호출 흐름을 근거와 함께 정리합니다. 쓸 권한이 있는 프로그램만 대상으로 합니다.
오래된 시스템을 새로 옮길 때계산 규칙을 뽑은 뒤, 같은 입력을 구버전과 새 버전에 넣어 결과를 비교하는 테스트를 먼저 만듭니다.
내가 만든 앱의 보안 점검배포한 웹 화면 코드나 설치형 프로그램을 직접 열어 보고, 밖에서 보이는 업무 규칙, 키, 주소가 있는지 확인합니다. "이제 누구의 AI든 출시된 앱을 읽을 수 있다"는 말이 나온 이유입니다.
버전 사이에 바뀐 점 확인두 배포본을 비교해 새로 생긴 통로나 사라진 검사를 찾습니다. REA에 버전 비교 기능이 들어 있습니다.
웹 화면 동작 연구공개된 웹 게임이나 화면의 움직임 규칙을 찾아 내 사이트에 새로 구현합니다. 아래 실습 1이 이것입니다.

설치 부탁하기

REA는 일주일 사이에 큰 버전이 세 번 바뀔 만큼 빨리 바뀌고, 이름이 비슷한 가짜 안내도 돌고 있습니다. 그래서 공식 출처만 쓰고 버전을 고정합니다. Node.js 22.19 이상이 필요합니다.

회사망에서 인증서 오류(certificate, self-signed 같은 단어)가 나오면 그 문구를 그대로 Claude에게 전달하세요.

실습 1. 크롬 공룡 게임의 속도 규칙 찾기

인터넷이 끊기면 크롬에 나오는 공룡 게임은 원본 코드가 BSD 라이선스로 공개되어 있어 마음 놓고 연습할 수 있습니다. REA 공식 사례에서는 "시작 속도 6, 한 번 갱신할 때마다 0.001씩 빨라지고, 최대 13"이라는 규칙을 찾아냈습니다. 같은 답이 나오는지 직접 확인해 보세요.

웹 게임은 원래 코드가 보이기 때문에 REA 없이도 Claude가 읽을 수 있습니다. 차이는 근거가 정리되어 나오는지입니다. REA 없이 한 번, REA로 한 번 해서 결과를 비교해 보면 좋습니다.

실습 2. 윈도우 그림판 뜯어보고 새 기능 붙이기

윈도우에 들어 있는 그림판은 누구나 가진 프로그램이라 바로 시도해 볼 수 있습니다. 국내 유튜브 영상에서는 REA로 그림판을 다시 만들고, 원래 없던 "붙여 넣은 그림 목록" 패널을 11분 만에 붙였습니다. 윈도우 프로그램은 Ghidra와 Java(JDK 21)가 필요하고, 윈도우에서의 Ghidra 연결은 아직 실험 단계라 첫 실행에 몇 분이 걸리거나 실패할 수 있습니다.

분석이 실패해서 "관찰하기"로 바뀌어도 괜찮습니다. 포토샵을 따라 만든 ArtCraft도 원본을 뜯어보지 않고 동작을 관찰하는 방식으로 만들었습니다.

완성 예시: 웹 그림판 연습작

실습 2를 실제로 해서 만든 결과물입니다. REA로 그림판의 채우기 기능이 들어 있는 파일(BasePaint.dll)을 찾아 규칙을 확인하고, 원본 코드와 그림은 쓰지 않고 그 규칙대로 새로 짰습니다. 붙여 넣은 그림 목록(최근 10개, 다시 붙이기, 다시 복사)도 붙였습니다.

웹 그림판 연습작
REA로 확인한 채우기 규칙내용
무엇과 비교하나바로 옆 칸이 아니라 처음 누른 곳의 색과 비교합니다.
어디로 번지나위, 아래, 왼쪽, 오른쪽 4방향으로만 번집니다. 대각선으로는 번지지 않습니다.
허용 오차투명도와 빨강, 초록, 파랑 네 값의 거리가 "허용 오차 × 510" 이하이면 같은 색으로 봅니다. 0%는 똑같은 색만 칠합니다.
칠하는 색투명도는 항상 불투명으로 고정됩니다.

실제로 해 보니 분석 한 번에 2분 30초 정도 걸렸습니다. "Request timed out"이 나오면 Claude에게 도구 대기 시간을 늘려 달라고 부탁하세요. 그림판 파일은 일반 폴더로 복사한 뒤 분석했습니다.

잘 쓰는 법

  • 좁게 묻습니다. "이 앱 분석해 줘"보다 "채우기 버튼을 누르면 무슨 일이 일어나는지"가 좋습니다. 넓게 물으면 결과가 너무 길어 Claude가 앞 내용을 잊습니다.
  • 근거를 요구합니다. "근거와 모르는 부분을 같이 보여 줘"를 꼭 붙입니다.
  • 정답은 테스트로 판정합니다. 원본과 같은 입력을 넣고 결과를 비교하는 테스트를 먼저 만듭니다. "테스트 없이 하는 리버스 엔지니어링은 그냥 감"이라는 말이 나올 정도입니다.
  • AI의 꼼수를 막습니다. 게임 하나를 통째로 복원한 개발자는 AI가 검증 기준을 슬쩍 고치려 들어서 검증 스크립트를 잠갔습니다. 그의 말은 "할 일이 해석의 여지를 남기면 AI는 꼼수를 쓰고 싶어 한다"였습니다.
  • REA 없이 먼저 해 봅니다. 맥의 미리보기 앱을 따라 만드는 비교에서는 화면만 본 일반 Claude가 먼저 끝났습니다. 일반 방법으로 먼저 해 보고, 더 깊이 봐야 할 때 REA를 씁니다.
하지 말아야 할 것
  • 남이 파는 프로그램을 분석해 똑같이 만들어 팔거나 배포하기. 우리 저작권법은 호환에 필요한 부분만 좁게 분석을 허용합니다.
  • 회사 프로그램, 고객사 프로그램, 회사 소스를 분석 대상으로 쓰기. 분석 결과는 AI 회사로 넘어갑니다.
  • 복제 방지, 라이선스 검사, 게임 보안 우회. REA도 금지 용도로 정해 두었습니다.
  • 정품이 아닌 IDA, Hopper 같은 유료 분석 도구 쓰기.
