07

스킬로 일하는 법

유명한 AI 코딩 스킬 7종이 요구사항, 설계, 구현, 검증 네 단계에서 각각 어떻게 다르게 일하는지 인사시스템 휴가 기능 하나로 비교합니다. 그다음 개발 스킬 하나와 UI 스킬 하나를 직접 설치해 전후 차이를 확인합니다.

스킬이란

스킬은 Claude가 특정 일을 할 때 따르는 작업 방법을 적은 파일 묶음입니다. 폴더 하나에 SKILL.md(언제 쓰는지, 어떤 순서로 일하는지)와 필요한 참고 파일이 들어 있습니다. 여러 스킬과 명령, 훅을 묶어 배포하는 단위가 플러그인이고, 플러그인을 모아 둔 목록이 마켓플레이스입니다. Claude Code에서는 /plugin 명령으로 설치합니다.

지금 공개된 유명 스킬들은 모두 "요구사항을 정리하고, 설계하고, 구현하고, 검증한다"고 소개합니다. 그런데 실제로 써 보면 어디에 힘을 주는지가 다릅니다. 어떤 스킬은 질문을 끝까지 하고, 어떤 스킬은 문서를 기준으로 삼고, 어떤 스킬은 리뷰를 여러 갈래로 나눕니다. 그래서 고르는 기준은 "가장 유명한 것"이 아니라 내 작업 방식에서 가장 약한 단계를 채워 주는 것입니다.

공통 예시: 인사시스템의 휴가 신청과 승인

SaaS형 인사시스템에 휴가 기능을 새로 만든다고 가정합니다. 이 장의 모든 비교는 이 기능 하나로 합니다. 데이터는 모두 가짜입니다.

구분내용
기본 흐름직원이 휴가를 신청하고, 팀장이 승인하면 남은 연차가 줄어듭니다.
빠뜨리기 쉬운 예외팀장이 없거나 부재 중일 때 누가 승인하나, 반차는 어떻게 세나, 승인 뒤 취소하면 연차를 돌려주나, 남은 연차보다 많이 신청하면 막나

예외가 정리되지 않은 채 코드를 받으면, 화면은 그럴듯해도 운영에서 바로 문의가 들어옵니다. 스킬들이 갈리는 지점이 바로 여기입니다.

1단계. 요구사항: 무엇을, 왜 만드나

스킬휴가 기능에서 하는 일
Superpowers brainstorming코드를 쓰기 전에 질문을 한 번에 하나씩 합니다. "누가 쓰나", "왜 지금 필요한가"부터 묻고, 답을 모아 설계 문서로 만듭니다.
Matt Pocock /grill-me, /grill-with-docs결정하지 않은 예외를 끝까지 파고듭니다. "팀장이 없으면?"처럼 빈 곳을 찾습니다. grill-with-docs는 용어와 결정 사항을 문서로 남깁니다.
Addy Osmani interview-me, idea-refine질문으로 의도를 확인하고, 아이디어를 개발 가능한 요구사항 문장으로 다듬습니다.
gstack /office-hours기능을 정하기 전에 "이걸 만들 필요가 있나"를 먼저 따집니다. 실제 사용자 문제가 무엇인지 확인합니다.
Spec Kit /speckit-specify, clarify요구사항을 명세 문서로 씁니다. 빠진 규칙을 보완하고, 이 문서를 끝까지 기준으로 삼습니다.
Feature Dev /feature-dev기존 프로젝트 코드를 먼저 탐색합니다. 이미 있는 직원, 조직 구조와 어떻게 연결할지 묻습니다.
pstack /pstack:poteto-mode목표와 완료 조건을 주면, 새 기능인지 버그 수정인지 보고 맞는 작업 절차를 고릅니다.

2단계. 설계: 어떻게 나눠 만드나

스킬휴가 기능에서 하는 일
Superpowers writing-plans고칠 파일, 만들 테스트, 순서를 작은 작업 단위로 적은 계획을 씁니다. 작업 중에 AI가 방향을 잃지 않게 합니다.
Addy Osmani planning-and-task-breakdown작업마다 완료 기준과 먼저 끝나야 할 작업을 정합니다.
Spec Kit plan, tasks명세에서 기술 구조를 잡고 tasks.md로 작업을 나눕니다. 명세의 요구사항이 작업에서 빠지지 않게 연결합니다.
Feature Dev기존 코드 재사용과 새 모듈 분리 같은 설계안을 여러 개 내고 장단점을 비교해 고르게 합니다.
gstack /plan-ceo-review, /plan-eng-review, /design-review같은 계획을 제품, 기술, 화면 관점에서 따로 검토합니다. 예를 들어 승인이 실패했을 때 사용자가 어떻게 다시 시도하는지까지 봅니다.
Matt Pocock wayfinder한 번에 끝나지 않는 큰 작업의 결정 사항을 나눠, 여러 작업 세션에 걸쳐 이어 갈 수 있게 합니다.
pstack architect, arena타입, 함수 모양, 모듈 구조를 먼저 정합니다. arena는 여러 에이전트에게 다른 설계안을 만들게 한 뒤 좋은 점을 합칩니다.

3단계. 구현: 어떤 순서로 코드를 쓰나

스킬휴가 기능에서 하는 일
SuperpowersTDD(테스트 주도 개발)를 강하게 지킵니다. "남은 연차보다 많이 신청하면 거절" 테스트를 먼저 쓰고 실패를 확인한 뒤 코드를 씁니다. 작업을 잘게 나눠 서브에이전트(작업 하나를 맡는 별도 Claude)에게 맡길 수 있습니다.
Addy Osmani incremental-implementation화면, 서버, 저장을 관통하는 얇은 조각 하나(예: 신청 저장)를 완전히 동작시키고 나서 다음 조각(승인)으로 넘어갑니다.
Spec Kit implementtasks.md의 순서와 의존 관계대로 구현합니다.
Feature Dev고른 설계안과 기존 코드 규칙에 맞춰 구현합니다.
Matt Pocock지금 방식은 그대로 두고, 필요한 스킬(TDD, 구조 개선 등)만 골라 붙입니다.
gstack, pstack앞 단계의 계획과 절차를 따라 관련 스킬을 이어서 실행합니다.

4단계. 검증: 다 됐다고 어떻게 믿나

스킬휴가 기능에서 하는 일
Superpowers테스트 통과와 함께, 서브에이전트가 쓴 코드가 요구사항을 지켰는지와 품질을 따로 검토합니다.
Feature Dev리뷰 에이전트 셋이 동시에 봅니다. 하나는 단순함과 중복, 하나는 버그와 정확성, 하나는 프로젝트 규칙 준수입니다.
gstack /review, /qa코드 검토와 실제 동작 확인을 나눕니다. 빌드가 성공해도 앱을 띄워 신청부터 승인까지 직접 눌러 봅니다.
Spec Kit analyze, converge명세와 계획이 서로 맞는지 점검하고, 구현 뒤 아직 안 된 요구사항을 찾아 작업 목록에 다시 넣습니다. 다 채워질 때까지 반복합니다.
Addy OsmaniTDD 외에 코드 리뷰, 보안 점검, 브라우저 테스트 스킬을 따로 제공합니다.
pstack interrogate서로 다른 AI 모델이 같은 변경을 따로 검토하게 해서, 공통 지적과 의견 차이를 비교합니다. 문제를 재현하고 고친 뒤 실제 실행 결과를 증거로 남깁니다.

한눈에 비교

스킬시작힘을 주는 곳설치 부담
Superpowers자동 (설치하면 알아서 발동)정해진 절차와 TDD를 끝까지 지키기낮음: 공식 마켓 한 줄
Matt Pocock/grill-me집요한 예외 질문, 필요한 스킬만 골라 쓰기낮음: 공식 마켓 한 줄
Addy Osmani/spec작은 조각으로 하나씩 완성, 폭넓은 실무 원칙중간: 마켓 추가 필요, SSH 키가 없으면 HTTPS로

더 가볍게 명세부터 시작하고 싶으면 OpenSpec(/opsx:propose), 작업할 때마다 배운 점을 문서로 쌓아 다음 작업을 쉽게 만들고 싶으면 Compound Engineering(/ce-brainstorm)도 있습니다.

비슷한 절차를 가진 스킬을 여러 개 켜면 서로 겹치거나 충돌합니다. 질문이 두 번 나오고, 계획 문서가 두 벌 생깁니다. 내가 가장 보완하고 싶은 단계를 정하고 하나씩 써 본 뒤 맞는 것만 남깁니다.

실습 1. 개발 스킬 설치: Superpowers

설치 전과 후에 같은 부탁을 보내 차이를 봅니다. 관전 포인트는 질문을 하는 방식입니다. 한꺼번에 묻고 기본안을 내미는지, 한 번에 하나씩 업무 흐름부터 묻는지 봅니다.

  1. 설치 전에 한 번 부탁합니다

    빈 연습 폴더에서 Claude Code를 열고 아래 부탁을 그대로 보냅니다. 답을 저장해 둡니다.

  2. 설치합니다

    Claude Code 입력창에 /plugin install superpowers@claude-plugins-official 를 입력합니다. 끝나면 Claude Code를 다시 시작합니다.

  3. 같은 부탁을 다시 보내고 비교합니다

    새 연습 폴더에서 같은 부탁을 보냅니다. 이번에는 brainstorming 스킬이 발동해 질문을 하나씩 합니다. 질문에 답해 가며 설계 문서와 계획이 만들어지는 과정을 끝까지 따라가 봅니다.

일부러 짧고 모호하게 부탁합니다. 스킬이 빈 곳을 어떻게 채우는지 보려는 것입니다.

실제로 해 본 결과

강사 PC에서 다른 플러그인과 개인 설정을 모두 끄고, 같은 부탁을 스킬 없이 한 번, Superpowers만 켜고 한 번 보냈습니다. 예상과 달리 스킬이 없어도 코드를 바로 쓰지 않고 질문부터 했습니다. 이 PC에는 회사가 정한 "불명확하면 질문" 지침이 들어 있어서 끌 수 없었기 때문입니다. 그래도 질문하는 방식은 분명히 달랐습니다.

구분스킬 없음Superpowers 설치 뒤
스킬 호출없음superpowers:brainstorming 호출 기록 있음
질문 방식질문 4묶음을 한 번에 보여 주고, 답이 없으면 정적 HTML 목업으로 바로 만들겠다는 기본안 제시질문 하나만 던짐. 그 질문도 화면이 아니라 업무 흐름(신청을 마칠 때까지의 순서)을 물음
실제 답 발췌"결과물 범위는 어디까지인가요? (해석이 여러 가지라서 여쭙니다)""직원이 이 화면에서 휴가를 신청할 때 어떤 과정을 거치게 되는지, 처음 들어와서 신청을 마칠 때까지를 순서대로 설명해 주시겠어요?"

내 PC에 회사 지침이나 개인 CLAUDE.md가 없다면 스킬 없는 쪽은 질문 없이 바로 코드를 쓸 수도 있습니다. 결과가 위와 달라도 이상한 것이 아닙니다. 어떤 설정이 답을 바꿨는지 확인하는 것도 실습입니다.

설치 뒤 알아 둘 것
  • Superpowers는 설치하면 이후 모든 작업에 자동으로 끼어듭니다. 실습 2 전에는 /plugin 화면에서 잠시 끕니다(Disable). 다시 쓸 때 켭니다.
  • 기본으로 사용 통계를 보냅니다. 끄려면 환경 변수 SUPERPOWERS_DISABLE_TELEMETRY를 1로 둡니다.
  • 질문을 건너뛰고 바로 진행하고 싶으면 "질문 없이 바로 진행해"라고 말하면 됩니다.

실습 2. UI 스킬 설치: frontend-design

Anthropic이 공식으로 만든 UI 스킬입니다. AI가 만든 화면에서 흔히 보이는 "어디서 본 듯한" 배치와 색을 피하고, 목적에 맞는 디자인 방향을 먼저 정한 뒤 화면을 만들게 합니다.

  1. 스킬 없이 한 번 만듭니다

    빈 연습 폴더에서 아래 부탁을 보내고 만들어진 index.html을 브라우저로 엽니다.

  2. 설치합니다

    /plugin install frontend-design@claude-plugins-official 를 입력하고 Claude Code를 다시 시작합니다.

  3. 새 폴더에서 스킬을 직접 불러 같은 부탁을 보내고 두 화면을 나란히 엽니다

    부탁 앞에 /frontend-design:frontend-design 을 붙여 보냅니다. 글자 크기의 대비, 색, 여백, 강조 방식이 어떻게 달라졌는지 봅니다.

실제로 해 본 결과

같은 방법으로 스킬 없이 한 번, frontend-design만 켜고 여러 번 보냈습니다. 부탁만 보냈을 때는 스킬이 목록에 있어도 자동으로 호출되지 않았고, 스킬 없을 때와 거의 같은 화면이 나왔습니다. 그래서 아래 "설치 뒤" 화면은 /frontend-design:frontend-design 으로 직접 불러 만든 결과입니다. 자동 발동을 기대하지 말고 필요할 때 직접 부르는 스킬로 생각하는 편이 맞습니다.

구분스킬 없음frontend-design 직접 호출
첫인상파란 헤더, 요약 카드 3개, 아래쪽 표. 흔히 보는 관리 화면큰 "7.5일 남았어요" 문구가 먼저 보이는 화면
입력브라우저 기본 선택 상자와 날짜 입력알약 모양 휴가 종류 버튼, 공휴일이 표시된 직접 만든 달력
연차 표시숫자 카드15칸 블록 막대(사용은 남색, 결재 대기는 빗금)
그 밖없음업무 대행자 항목, 움직임 줄이기 설정 대응
파일 크기약 9KB약 27KB

다른 UI 스킬도 같은 방법으로 비교해 볼 수 있습니다.
