앱과 터미널 도구를 둘 다 설치하는 이유

공식 문서에 따르면 데스크톱 앱의 Code 탭에는 Claude Code가 이미 들어 있어서, 앱만 설치해도 Code 탭은 쓸 수 있습니다. 그래도 터미널용을 따로 준비하는 데에는 이유가 있습니다.

첫째, 이후 장에서 쓰는 명령(스킬과 플러그인 설치, hyperframes 실행)은 터미널에서도 같은 Claude가 일할 수 있어야 편합니다. 둘째, 앱과 터미널은 같은 설정 파일과 스킬을 함께 씁니다(공식 문서). 한쪽에서 해 둔 설정이 다른 쪽에서도 이어집니다. 셋째, "설치를 Claude에게 부탁해 보는 경험" 자체가 이 교육의 목표입니다.

Claude Code란?

Claude가 대화만 하는 것이 아니라, 내 PC에서 직접 손을 움직여 일하게 해 주는 기능입니다. "이 폴더에 메모 파일을 만들어 줘"라고 하면 정말로 파일이 생깁니다. 대신 Claude가 내 PC에서 하는 행동에는 내 허락이 필요하고, 그 허락 방식이 뒤에 나오는 "권한 모드"입니다.

Git 설치하기

바로 아래에서 GitHub의 저장소를 내 PC로 내려받을 때 Git이 필요합니다. 아직 Claude의 Code 탭을 열기 전이므로 이 단계는 내가 직접 합니다. 먼저 이미 설치되어 있는지 확인하세요.

Windows

  1. cmd 창에서 설치 여부 확인

    Win + R을 누르고 cmd를 입력한 뒤 Enter를 누릅니다. 열린 검은 창에 아래 명령을 입력하세요. git version 2.x.x 같은 줄이 나오면 이미 설치된 것이니 다음 단계로 넘어갑니다.

  2. 없으면 winget으로 설치

    "인식되지 않습니다"가 나오면 같은 창에 아래 명령을 입력합니다. Windows에는 winget이라는 설치 도구가 기본으로 들어 있습니다. 사용자 계정 컨트롤 창이 뜨면 방금 내가 시작한 설치일 때만 예를 누르세요. 끝나면 cmd 창을 닫고 새로 열어 git --version을 다시 입력해 확인합니다.

    winget이 없다고 나오면 git-scm.com/downloads/win에서 설치 파일을 받아 실행합니다. 모든 화면에서 기본값으로 다음(Next)을 누르면 됩니다. 회사 PC에서 설치가 막히면 IT 담당자에게 "Git for Windows 설치"를 요청하세요.

Mac

터미널에서 git --version을 입력합니다. 설치되어 있지 않으면 "명령줄 개발자 도구를 설치하시겠습니까?" 안내 창이 뜹니다. 설치(Install)를 누르고 끝날 때까지 기다린 뒤 다시 확인하세요. 몇 분 걸릴 수 있습니다.

GitHub 가입과 저장소 준비

GitHub 가입하기

브라우저에서 github.com/signup으로 가입합니다. 이미 계정이 있으면 로그인만 하세요. 이메일은 앞으로도 쓸 개인 이메일을 권장합니다. 가입 직후 이메일 인증 안내가 보이면 메일의 링크를 눌러 인증을 끝내세요(인증하지 않으면 저장소를 만들 수 없습니다). 이 교육에서는 연습용 사이트 파일만 올리고, 회사 문서나 고객 정보는 올리지 않습니다.

사이트용 저장소 ai-site 만들기

사이트 파일을 담을 GitHub 저장소(파일 보관함)를 웹에서 먼저 하나 만듭니다. 이름은 ai-site로 하고, 안은 비워 둡니다. 이 빈 보관함을 아래에서 내 PC로 내려받으면, 그 폴더가 앞으로 사이트를 만드는 작업 폴더가 됩니다.

  1. 새 저장소 만들기 화면 열기

    github.com에 로그인한 상태에서 오른쪽 위의 + 버튼을 누르고 New repository를 고릅니다.

    1. +
    2. New repository

  2. 이름과 공개 범위 정하기

    Repository name에 ai-site를 입력합니다. 공개 범위는 Private을 고릅니다. 설명(Description)은 비워도 됩니다.

    왜 Private인가요?
    • 연습 중인 파일이 다른 사람에게 보이지 않습니다.
    • 비공개 저장소는 내려받을 때 로그인이 필요해서, 아래 내려받기 한 번으로 GitHub 연결까지 끝납니다.
    • Vercel 무료(Hobby) 플랜도 내 개인 계정의 Private 저장소를 배포할 수 있습니다. 완성된 사이트는 Vercel 주소로 누구나 볼 수 있습니다.

  3. 아무것도 추가하지 않고 만들기

    README, .gitignore, 라이선스를 추가하는 선택지는 모두 꺼 둔 채로 둡니다(빈 저장소). 그다음 Create repository를 누릅니다. 화면 구성과 문구는 업데이트로 조금 다를 수 있습니다.

  4. 저장소 주소 복사하기

    만들어지면 "Quick setup" 안내 화면이 나옵니다. HTTPS가 선택된 상태에서 보이는 주소 https://github.com/[내 사용자 이름]/ai-site.git 오른쪽의 복사 버튼을 누릅니다. 아래에서 바로 씁니다.

Code 탭에서 ai-site 폴더 열기

Claude는 내가 지정한 폴더 안에서만 일합니다. 방금 내려받아 생긴 ai-site 폴더가 앞으로 사이트를 만드는 작업 폴더이고, GitHub의 ai-site 저장소와 이미 연결되어 있습니다. 이 폴더를 Claude 앱에서 엽니다.

  1. Code 탭 열기

    Claude 앱의 Code 탭을 누릅니다. 업그레이드 안내가 나오면 유료 플랜이 필요하다는 뜻입니다. 온라인 로그인을 요구하면 로그인을 끝내고 앱을 한 번 껐다가 다시 켜세요(공식 문서 안내).

  2. 환경을 Local로 고르기

    입력창 근처에서 실행 환경을 고르는 곳이 있습니다. Local을 선택하세요. Local은 "내 컴퓨터의 파일을 직접 쓴다"는 뜻입니다. 같은 목록에 보이는 Cloud(인터넷상의 별도 환경에서 실행), SSH(다른 컴퓨터에 연결), WSL(Windows 안의 Linux 환경)은 지금은 쓰지 않습니다.

  3. Select folder로 ai-site 선택하기

    Select folder를 누르면 폴더를 고르는 창이 열립니다. 문서 아래의 ai-site 폴더를 찾아 선택하고, 창 아래쪽의 확인 버튼(Windows는 보통 "폴더 선택", Mac은 보통 "열기")을 누릅니다. 화면에 폴더 이름 ai-site가 표시되면 성공입니다.

  4. 모델과 권한 모드 확인하기

    입력창의 전송 버튼 옆에 모델을 고르는 목록과 권한 모드를 고르는 선택기가 있습니다. 모델은 기본값 그대로 두세요. 권한 모드는 다음 절에서 설명하는 Accept edits(파일 수정은 자동 승인)로 바꿉니다.

    대화 도중에 모델을 바꾸지 마세요

    지금 대화는 현재 모델 기준으로 캐시(빠르게 다시 쓰려고 임시로 저장해 둔 것)되어 있습니다. 대화 도중에 모델을 바꾸면 다음 메시지를 보낼 때 Claude가 지금까지의 대화 전체를 처음부터 다시 읽어야 해서, 사용 한도가 더 많이 소모됩니다. 아래처럼 확인 창이 뜨면 모델이 바뀌는 것이므로 취소를 누르세요. 모델을 바꾸고 싶다면 새 대화를 시작할 때 고르는 편이 한도를 아낍니다.

권한(허용) 질문 읽는 법

Claude Code는 내 PC에서 파일을 만들고 명령을 실행합니다. 그래서 "어디까지 알아서 해도 되는지"를 정하는 장치가 있습니다. 이것이 권한 모드입니다.

권한 모드란?

새로 온 인턴에게 일을 맡길 때를 떠올려 보세요. 처음에는 "서류를 고치기 전에 매번 보여 주세요"라고 하다가, 믿음이 생기면 "서류 정리는 알아서 하되 결재 올리기 전에는 꼭 물어보세요"로 바꿉니다. 권한 모드는 Claude에게 이 "물어보는 범위"를 정해 주는 설정입니다. 입력창 전송 버튼 옆의 선택기에서 언제든 바꿀 수 있습니다.

모드 이름하는 일이 교육에서는
Manual파일을 고치거나 명령을 실행하기 전에 매번 물어봅니다. 바뀌는 내용을 비교 화면(diff)으로 보여 주고 허용(Accept)과 거절(Reject) 중에서 고르게 합니다.쓰지 않아도 됩니다. 매번 허용을 눌러야 해서 실습 속도가 느려집니다.
Accept edits파일 수정과 폴더 만들기(mkdir), 파일 이동(mv) 같은 기본 파일 작업은 묻지 않고 하고, 그 밖의 명령은 계속 묻습니다.이 교육에서 쓰는 모드입니다. 파일 수정은 알아서 하고, 명령 실행(설치, 올리기 등)은 계속 물어보므로 안전하면서도 덜 번거롭습니다.
Plan파일을 읽고 조사만 한 뒤 계획을 제안합니다. 파일은 고치지 않습니다.큰 작업 전에 계획만 먼저 보고 싶을 때 씁니다.
Auto별도의 검사 장치가 위험한 행동을 걸러 주고, 평소에는 묻지 않고 진행합니다. 계정과 모델에 따라 목록에 없을 수 있습니다.목록에 있으면 써도 됩니다. 처음에는 Accept edits로 시작하는 것을 권합니다.
Bypass permissions모든 질문을 건너뛰고 실행합니다. 설정에서 켜야만 목록에 나타나며, 회사 계정은 조직 정책이 이를 정합니다.사용하지 않습니다.

예전 앱 버전에서는 이 모드들이 Ask permissions, Auto accept edits, Plan mode라는 이름으로 표시되었습니다. 이름은 달라도 같은 개념입니다.

핵심 장면: Claude에게 설치를 부탁하기

아래 부탁을 복사해 입력창에 붙여넣고 Enter를 누릅니다

직접 해보는 확인: 새 터미널에서 claude --version

Claude가 "설치했다"고 말했더라도, 내가 직접 새 터미널에서 확인해 보면 확신이 생깁니다. 이 확인은 앞으로도 도구가 이상할 때마다 쓰는 기본 습관입니다.

Windows

  1. 새 PowerShell 열기

    Win + X를 누르고 메뉴에서 Windows PowerShell(또는 "터미널")을 선택합니다. 시작 메뉴에서 "PowerShell"을 검색해도 됩니다. 깜빡이는 커서가 있는 창이 열립니다.

    창의 줄 맨 앞이 PS C:\Users\[내 이름]>처럼 PS로 시작하면 PowerShell이 맞습니다. PS 없이 C:\Users\[내 이름]>로 시작하면 CMD(명령 프롬프트)입니다. 이 경우 창을 닫고 PowerShell로 다시 여세요.

  2. 버전 확인 명령 입력

    아래 명령을 복사해 붙여넣고 Enter를 누릅니다. 네이티브 설치는 사용자 PATH에 등록되므로 cmd(명령 프롬프트)에서도 똑같이 동작합니다. PowerShell 창에서는 Ctrl + V 또는 마우스 오른쪽 클릭으로 붙여넣을 수 있습니다.

Mac

  1. 새 터미널 열기

    Command + Space를 눌러 Spotlight 검색을 열고 Terminal을 입력한 뒤 Enter를 누릅니다. 커서가 깜빡이는 창이 열리면 터미널입니다.

  2. 버전 확인 명령 입력

성공하면 이렇게 보입니다

claude --version을 입력하면 곧바로 한 줄이 나옵니다. 버전 숫자 뒤에 괄호로 (Claude Code)가 붙은 모양입니다. 예: 2.1.290 (Claude Code). 숫자는 설치 시점에 따라 다릅니다. 숫자가 보이면 성공입니다.

이런 문구가 나오면 실패입니다

Windows PowerShell에서 "claude ... 인식되지 않습니다"(영어로는 is not recognized), Mac에서 zsh: command not found: claude가 나오면 PATH에 아직 등록되지 않았다는 뜻입니다. 먼저 창을 닫고 새 창에서 다시 해 보세요. 그래도 같으면 이 장 끝의 "막히면 Claude에게 그대로 전달하세요"를 따라 하세요.
