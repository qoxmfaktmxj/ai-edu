05

시험하고 고치기

까다로운 입력 두 개로 내 에이전트를 시험하고, 규칙 한 줄을 더한 뒤 같은 입력으로 다시 시험합니다. 마지막에 무엇을 만들었고 언제 쓸지 한 줄로 나눕니다.

1. 까다로운 입력 두 개로 시험하기

실제 업무 메모처럼 완료한 일, 진행 중인 일, 전달받은 내용을 섞었습니다. 첫 번째는 숫자와 집계 기준이 서로 다르고, 두 번째는 초안과 확정된 결과를 구분해야 합니다. 내 업무로 만들었다면 같은 함정을 내 업무 말로 바꿔 보냅니다.

  • 첫 번째 숫자: 엑셀의 128건과 메일의 132건을 모두 적고 '확인 필요'로 남겼는지 봅니다. 더 최근에 확인한 숫자라는 이유만으로 128건을 정답으로 고르거나, 차이 4건을 중복 응답이라고 설명하면 실패입니다.
  • 첫 번째 집계: 발송 인원 150명을 응답 인원으로 쓰지 않았는지 봅니다. 교육 참석 기록을 합쳐 '직원 47명 교육 완료'라고 쓰면 중복 여부를 무시한 것입니다. 식당 의견을 최다 의견으로 단정하거나, 설문 보고일과 추가 교육 계획을 만들지 않았는지도 봅니다.
  • 두 번째 상태: 안내문은 일부 항목을 수정한 검토 단계입니다. 팀장님의 반응을 최종 승인으로 바꾸면 실패입니다. 일정표 파일의 초안 작성은 완료로 적을 수 있지만, 교육 일정 확정, 교육장 예약, 안내 메일 발송까지 완료로 쓰면 실패입니다.
  • 두 번째 계획: 희망 사항인 '다음 주쯤 배포'와 예시인 '수요일 오후'를 확정 일정으로 쓰지 않았는지 봅니다. 다음 주 칸을 채우려고 '담당 부서 확인 후 배포 예정' 같은 계획을 만들면 실패입니다. 계획이 정해지지 않았다고 표시하거나, 필요한 확인 사항을 확정된 계획과 구분하면 됩니다.

2. 규칙 한 줄 더하기

방금 틀린 곳이나 1장에서 적어 둔 아쉬운 점을 규칙 한 줄로 바꿔, 구성 탭 안내의 '꼭 지킬 것'에 넣습니다. 고치기 전 안내는 메모장에 복사해 둡니다.

3. 같은 입력으로 다시 시험하기

1의 두 메모를 다시 보내 달라졌는지 봅니다. 그래도 틀리면 규칙을 더 구체적으로 고칩니다. 예를 들어 "숫자를 지킨다"보다 "메모끼리 숫자가 다르면 두 값을 모두 적는다"가 잘 지켜집니다.

4. 한 줄 공유

무엇을 맡기는 에이전트인지, 언제 쓸지, 어떤 규칙을 넣었더니 무엇이 달라졌는지 한 줄로 나눕니다.

수업 뒤에

  • 다음 주에 실제로 한 번 써 보고, 아쉬운 점이 생길 때마다 규칙 한 줄씩 더합니다. 문서 도우미도 이렇게 자랐습니다.
  • 실제 업무 자료를 넣을 때는 1장의 보안 수칙을 다시 확인합니다.
