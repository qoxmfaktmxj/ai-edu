02

만드는 과정 확인하기

1장에서 써 본 문서 도우미를 만든 순서와, 써 보면서 고친 점입니다. 마지막에 3~5장에서 함께 만들 예시 에이전트의 안내를 봅니다.

만든 순서

  1. 1. 빌더에 만들 에이전트를 설명했습니다

    에이전트 만들기의 설명 탭에 "업무 메모를 보고서로 바꾸고, 글을 다듬는 에이전트"라고 적어 이름, 설명, 안내 초안을 받았습니다.

  2. 2. 안내를 직접 고쳤습니다

    구성 탭에서 안내를 역할, 기술 선택, 공통 원칙처럼 용도별로 나눠 다시 썼습니다. 요청에 맞는 작업을 고르고, 원문의 사실을 지키고, 결과를 점검하는 규칙입니다.

    덩어리실제 문장 예
    역할업무 메모를 보고서로 만들고, 글을 다듬고, 어려운 내용을 그림으로 쉽게 설명합니다.
    기술 선택보고서, 메일, PPT처럼 형식을 정한 요청에 "쉽게"가 붙으면 그 형식 안에서 쉬운 말로 설명합니다.
    공통 원칙자료에 없는 담당자, 기한, 원인, 성과는 '확인 필요'로 표시합니다.
    문체글 다듬기 요청은 사용자가 준 원문의 문체를 그대로 유지합니다.
    문장 다듬기행위자가 원문에 있을 때만 피동문을 능동문으로 바꿉니다. 원문에 없는 담당자를 만들지 않습니다.
    파일 제공파일을 실제로 만들지 못했으면 실패했다고 알리고 대화창 결과만 제공합니다.
    마무리 점검답을 보내기 전에 숫자, 날짜, 이름, 확정 여부가 원문과 같은지 확인합니다.

  3. 3. 파일 제작 절차를 기술로 묶었습니다

    파일을 만드는 상세 절차는 isu-report 기술(ZIP 폴더)로 묶었습니다. PPT, Word, HTML 양식과 파일을 만드는 스크립트, PPT에서 선택해 쓸 아이콘 331개가 들어 있습니다. 회사 양식은 유지하되, 내용에 맞게 장을 합치거나 나누고 표, 글과 차트를 고릅니다.

    글 다듬기는 별도 기술 없이 안내의 '문장 다듬기' 규칙으로 처리합니다. 파일 형식을 정하지 않고 그림 설명을 요청하면 이미지 생성으로 그림 한 장을 만듭니다. 기술에는 파일 제작 절차를, 안내에는 작업 선택과 공통 규칙을 두었습니다.

  4. 4. 나머지를 설정했습니다

    파일을 만들기 위해 코드 인터프리터를 켜고, 추천 프롬프트를 넣고, 응답 모드를 깊이 생각하기로 정했습니다.

  5. 5. 써 보고 고쳤습니다

    시험하면서 나온 문제마다 규칙을 하나씩 더했고, 파일은 AI가 직접 쓰지 않고 스크립트로 만들게 바꿨습니다.

    써 보니 생긴 문제바꾼 것
    숫자가 슬쩍 바뀌었다원문의 숫자, 단위, 날짜, 고유명사를 그대로 옮기는 규칙
    메모에 없는 담당자가 생겼다자료에 없는 내용은 '확인 필요'로 표시하는 규칙
    '검토 중'이 '완료'가 됐다확정 여부를 원문 그대로 유지하는 규칙
    숫자 앞에 '약', '수준'이 붙었다보내기 전에 원문에 없던 표현을 지우는 마무리 점검
    로고를 글자로 흉내 낸 보고서가 나왔다보고서 파일은 기술의 스크립트로만 만드는 규칙
    다듬기 결과에 보고서 목차가 붙었다윤문은 기술 없이 문장 다듬기 규칙으로 처리하고 보고서 목차를 붙이지 않는 규칙
    아이콘을 요청했더니 모든 장에 붙었다의미 구분에 도움이 될 때만 쓰고, 표와 글로 충분하면 생략하는 규칙
    이전 예시의 숫자와 이름이 섞였다예시는 구조와 문체만 참고하고, 사실은 이번에 준 자료에서만 가져오는 규칙
    배치 검사는 통과했지만 중요한 조건이 빠졌다배치 검사와 별도로 최종 본문을 원문과 대조하는 절차
