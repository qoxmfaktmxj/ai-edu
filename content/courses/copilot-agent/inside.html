03

만드는 과정 확인하기

2장에서 써 본 문서 도우미를 만든 순서입니다. 무엇을 했고, 써 보면서 무엇을 바꿔 지금 모양이 됐는지 정리했습니다.

만든 순서

  1. 1. 빌더에 만들 에이전트를 설명했다

    에이전트 만들기의 설명 탭에 "업무 메모를 보고서로 바꾸고, 글을 다듬는 에이전트"라고 적어 이름, 설명, 안내 초안을 받았다.

  2. 2. 안내를 직접 고쳤다

    구성 탭에서 안내를 여섯 덩어리로 나눠 다시 썼다. 약 3,000자다.

    덩어리실제 문장 예
    역할업무 메모를 보고서로 만들고, 글을 다듬고, 어려운 내용을 그림으로 쉽게 설명합니다.
    기술 선택보고서나 메일처럼 형식을 정한 요청에 "쉽게"가 붙으면 그림 설명을 쓰지 않고 그 형식 안에서 쉬운 말로 씁니다.
    공통 원칙자료에 없는 담당자, 기한, 원인, 성과는 '확인 필요'로 표시합니다.
    문체글 다듬기 요청은 사용자가 준 원문의 문체를 그대로 유지합니다.
    파일 제공파일을 실제로 만들지 못했으면 실패했다고 알리고 대화창 결과만 제공합니다.
    마무리 점검답을 보내기 전에 숫자, 날짜, 이름, 확정 여부가 원문과 같은지 확인합니다.

  3. 3. 기술 3개를 만들어 올렸다

    작업별 상세 절차는 안내에 넣지 않고 기술(ZIP 폴더)로 따로 만들었다. 기술은 필요할 때만 읽힌다.

    기술폴더 안에 든 것
    보고서설명서(SKILL.md), HTML과 Word 양식, 파일을 만드는 스크립트
    글 다듬기설명서 하나
    그림 설명설명서, 업무용 아이콘 331개, 장면을 그리는 스크립트

  4. 4. 나머지를 설정했다

    코드 인터프리터를 켜고(파일을 만들려면 필요), 업로드 지식 파일은 비우고(기술과 함께 쓸 수 없음), 추천 프롬프트를 넣고, 응답 모드를 깊이 생각하기로 정했다.

  5. 5. 써 보고 고쳐서 지금 모양이 됐다

    시험해 보니 아래 문제가 나왔다. 규칙을 더하고, 파일은 AI가 직접 쓰지 않고 스크립트로 만들게 바꿨다.

    써 보니 생긴 문제바꾼 것
    숫자가 슬쩍 바뀌었다원문의 숫자, 단위, 날짜, 고유명사를 그대로 옮기는 규칙
    메모에 없는 담당자가 생겼다자료에 없는 내용은 '확인 필요'로 표시하는 규칙
    '검토 중'이 '완료'가 됐다확정 여부를 원문 그대로 유지하는 규칙
    숫자 앞에 '약', '수준'이 붙었다보내기 전에 원문에 없던 표현을 지우는 마무리 점검
    로고를 글자로 흉내 낸 보고서가 나왔다보고서 파일은 기술의 스크립트로만 만드는 규칙
    다듬기 결과에 보고서 목차가 붙었다요청별로 쓸 기술을 정한 기술 선택 규칙
왜 만들었나

보고서 같은 문서를 만들 때 조금이라도 편해지지 않을까 하는 생각에 만들었습니다. 써 보니 아직 완벽하지는 않지만 꽤 쓸 만하게 나옵니다. 써 보시고 불편한 점을 알려 주시면 고치겠습니다.

나만의 에이전트 만들기

여러분은 기술 없이 안내만으로 만듭니다. 안내만으로도 반복 업무 하나를 맡기기에는 충분합니다.
