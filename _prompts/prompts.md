## 02 설치와 GitHub 준비, Claude Code 설치

### GitHub CLI 설치 부탁
```text
GitHub CLI(gh)를 설치해줘.
1) 먼저 git --version 으로 Git이 설치되어 있는지 확인하고, 없으면 winget install --id Git.Git -e 로 설치해줘.
2) 그다음 winget install --id GitHub.cli 로 GitHub CLI를 설치해줘.
3) 설치가 끝나면 gh --version 결과를 보여줘.
로그인은 내가 직접 할 거라서 gh auth login 은 실행하지 마. 내 허락이 필요한 단계가 나오면 무엇을 허락하는 건지 먼저 설명해줘.
```

### Claude Code와 Node.js 설치 부탁
```text
Claude Code와 Node.js를 이 PC에 설치해줘.
1. Claude Code가 이미 있는지 확인하고, 없으면 Anthropic 공식 문서의 네이티브 설치 방법으로 설치해줘. 다른 사이트의 설치 방법은 쓰지 마.
2. 설치 후 cmd, PowerShell, Mac 터미널 어디서든 claude 라고만 입력하면 실행되도록 PATH를 확인하고, 빠져 있으면 내 계정 범위에서만 추가해줘.
3. Node.js가 없거나 22 미만이면 LTS 버전으로 설치해줘. Windows는 winget(OpenJS.NodeJS.LTS)으로, Mac은 nodejs.org 설치 파일을 내가 직접 설치하는 방법을 순서대로 알려줘. 이미 충분하면 설치하지 말고 알려만 줘.
4. 관리자 권한이 필요한 작업이나 다른 설정 변경, Homebrew 같은 새 도구 설치는 하지 마.
5. 각 단계 전에 무엇을 할지 한 줄로 알려주고, 마지막에 설치한 것과 버전을 쉬운 한국어로 정리해줘.
```

```text
[오류 문구를 그대로 붙여넣기]

```

### 2장 준비 상태 확인
```text
이 PC의 준비 상태를 확인해줘. 파일은 아무것도 바꾸거나 올리지 말고 확인만 해줘.
1. Git이 설치되어 있고, git config 에 user.name 과 user.email 이 설정되어 있는지
2. 지금 폴더가 ai-site 이고 GitHub 저장소와 연결되어 있는지 (git remote -v 와 git ls-remote origin 이 오류 없이 끝나는지)
3. Claude Code 설치 여부 (claude --version, PATH에 없으면 전체 경로로)
4. Node.js 22 이상이 설치되어 있는지 (node --version)
각 항목을 O 또는 X로 표로 정리해줘. X가 있으면 원인과 해결 방법을 알려주고, 모두 O이면 "준비 완료"라고 답해줘.
```

## 03 Vercel 가입과 첫 배포

### 첫 사이트 index.html 만들고 올리기
```text
ai-site 폴더에 index.html 파일 하나로 첫 사이트를 만들어줘.
- 화면 가운데에 큰 제목 "[내 이름 또는 닉네임]의 첫 사이트"와 한 줄 소개 문장
- 배경색은 [좋아하는 색], 글자는 읽기 편한 크기
- 휴대폰 화면에서도 깨지지 않게 (반응형)
- 버튼 하나를 누르면 인사말 문구가 바뀌는 간단한 동작
만든 다음 내 PC의 브라우저에서 열어 볼 수 있게 열어줘. 내가 확인하고 괜찮다고 하면, GitHub 저장소 ai-site 의 main 브랜치에 올려줘.
회사 자료나 개인정보는 파일에 넣지 마.
```

### 제목 바꾸고 GitHub에 올리기
```text
ai-site 의 index.html 에서 큰 제목을 "[새 제목]" 으로 바꿔줘.
바꾼 뒤에 변경 내용을 "제목 변경" 이라는 메시지로 저장(commit)하고, GitHub 의 main 브랜치에 올려줘(push).
올린 다음 어떤 파일이 바뀌었는지 한 줄로 알려줘.
```

### 미리보기 브랜치로 올려 보기
```text
ai-site 에서 new-title 이라는 새 브랜치를 만들어줘.
그 브랜치에서 index.html 의 큰 제목을 "[시험용 제목]" 으로 바꾸고 commit 한 뒤, GitHub 에 new-title 브랜치로 올려줘.
main 브랜치에는 합치지 말고, 올린 뒤 브랜치 이름을 알려줘.
```

### Vercel CLI 설치 부탁
```text
Vercel CLI를 설치해줘.
먼저 node --version 으로 Node.js가 설치되어 있는지 확인하고, 없으면 설치 방법을 알려줘.
있다면 npm i -g vercel 로 전역 설치하고, 끝나면 vercel --version 결과를 보여줘.
로그인(vercel login)은 내가 직접 할 테니 실행하지 마.
```

### Vercel CLI로 배포 부탁
```text
vercel login 을 마쳤어. ai-site 폴더에서 Vercel CLI로 배포해줘.
처음 배포라서 프로젝트 연결 질문이 나올 거야. 프로젝트 이름은 ai-site 로 하고, 기본값으로 진행하되 어떤 질문이 나왔고 무엇으로 답했는지 알려줘.
먼저 미리보기 배포를 하고, 내가 확인하면 vercel --prod 로 실제 주소(Production)에 배포해줘. 끝나면 주소를 알려줘.
```

### 3장 완료 확인
```text
내 Vercel 사이트 주소는 [https://프로젝트이름.vercel.app] 이야. 3장 결과물을 확인해줘. 파일은 아무것도 바꾸거나 올리지 말고 확인만 해줘.
1. ai-site 폴더에 index.html 이 있는지
2. index.html 이 GitHub 저장소 ai-site 의 main 브랜치에 올라가 있고, 로컬과 같은 내용인지 (git status, git ls-remote origin 등)

4. 저장소가 Vercel 프로젝트에 연결되어 main 에 올리면 자동으로 재배포되는 구조인지 (확인할 수 있는 범위에서, 어려우면 내가 Vercel 화면에서 볼 위치를 알려줘)
각 항목을 O 또는 X로 표로 정리해줘. X가 있으면 원인과 해결 방법을 알려주고, 모두 O이면 "완료"라고 답해줘.
```

### REA 설치 (선택)
```text
REA(Reverse Engineer Anything)를 Claude Code에 MCP로 설치해줘.
공식 출처는 GitHub morluto/rea, 사이트 rea.tools, npm 패키지 rea-agents 세 곳만 써. 이름이 비슷한 다른 패키지는 쓰지 마.

진행 방법:
1. GitHub morluto/rea 의 README를 먼저 읽고, 필요한 Node.js 버전과 내 PC의 node --version 을 비교해줘.
2. npm에서 rea-agents 최신 버전 번호를 확인하고, 그 버전으로 고정해서(rea-agents@버전) 진행해줘.
3. 설정을 바꾸기 전에 setup 을 --client claude_code --dry-run 으로 실행해서, 어떤 파일이 어떻게 바뀌는지 보여주고 내 허락을 받아줘.
4. 허락하면 실제로 적용하고, doctor 로 준비 상태를 확인해서 표로 정리해줘.
5. 오류가 나면 오류 문구를 그대로 보여주고 쉬운 말로 설명해줘.
6. 끝나면 새 세션을 시작해야 하는지 알려줘.
```

### REA 실습: 공룡 게임 속도 규칙
```text
REA로 크롬 공룡 게임의 속도 규칙을 찾아줘.
- 대상: GitHub wayou/t-rex-runner 를 내 사이트 폴더 밖의 새 폴더(예: 문서 폴더 아래 rea-lab)에 내려받은 것
- 알고 싶은 것: 시작 속도, 빨라지는 정도, 최대 속도
- 결과는 표로 정리하고, 근거(파일 이름, 줄 번호)를 붙이고, 직접 확인한 것과 추론한 것과 모르는 것을 나눠줘.

규칙을 확인하면, 내 사이트에 "속도 실험실" 섹션을 새로 만들어줘. 슬라이더로 속도를 바꾸면 달리는 캐릭터의 속도가 바뀌는 작은 화면이면 돼. 원본 코드와 그림은 복사하지 말고 규칙만 참고해서 새로 짜고, 섹션 아래에 원본 출처(Chromium, BSD 라이선스)를 적어줘.
```

### REA 실습: 그림판 기능 분석과 새 기능
```text
REA로 윈도우 그림판의 [채우기(페인트 통)] 기능이 어떻게 동작하는지 분석해줘. 개인 공부용이야.
- 그림판 설치 위치는 PowerShell 의 Get-AppxPackage 로 찾아줘.
- Ghidra나 JDK가 없으면 설치하기 전에 무엇을, 어디서, 얼마나 받는지 먼저 알려주고 내 허락을 받아줘.
- 결과는 근거(함수 위치, 문자열 등)를 붙이고, 직접 확인한 것과 추론한 것과 모르는 것을 나눠줘.
- 분석이 실패하면 억지로 진행하지 말고, 실패 이유를 알려준 뒤 그림판을 직접 써 보며 관찰하는 방식으로 바꿔줘.

분석이 끝나면 내 사이트에 웹 그림판 페이지를 새로 만들어줘. 펜, 지우개, 채우기, 색 고르기, 이미지 붙여넣기를 넣고, 원래 그림판에 없는 "붙여 넣은 그림 목록" 패널을 오른쪽에 추가해줘. 붙여 넣을 때마다 목록에 작은 그림이 쌓이고, 누르면 다시 캔버스에 놓이게 해줘. 그림판의 코드, 아이콘, 이름은 쓰지 말고 동작만 참고해서 새로 만들어줘.
```

## 05 완성작과 프롬프트

### 완성작 프롬프트: 별이 된 문장
```text
# 내 문장이 별이 되는 밤하늘 - 연출 우선 프롬프트

너는 미디어아트 전시를 만드는 인터랙티브 디자이너이자 프런트엔드 개발자다.
수천 개의 별 입자가 모여 문장이 되고, 손을 대면 흩어졌다가 다시 모이는 한 화면짜리 사이트를 만들어라.
제목은 "별이 된 문장.", 부제는 "손을 대면 흩어지고, 놓으면 다시 모입니다."

## 1. 사용자가 느껴야 할 것

- 열자마자 3초 안에 "와" 하는 순간이 있다. 어둠 속 한 점의 빛이 터지며 별 입자가 화면 가득 퍼졌다가 소용돌이치고, 제목 글자로 모인다.
- 마우스나 손가락을 대는 순간 화면 전체가 반응한다. 설명을 읽지 않아도 무엇을 하면 되는지 안다.
- 내 문장을 넣으면 별들이 그 문장으로 다시 모인다. 그 화면을 링크로 동료에게 보낼 수 있다.
- 가만히 있어도 별은 숨 쉬듯 반짝이고 아주 천천히 흔들린다.

## 2. 그림: 이미지 없이 코드로 그린다

- 사진, 이미지 파일, 외부 라이브러리를 쓰지 않는다. 모든 것을 Canvas 2D로 그린다.
- 배경: 거의 검은 남색(#05060f 근처)에서 가장자리로 갈수록 더 어두워지는 그라디언트, 아주 희미한 성운 빛 두세 덩어리, 움직이지 않는 작은 배경 별 수백 개.
- 입자: 크기 0.6 - 2.2px의 둥근 점. 대부분 흰색 계열이고 옅은 하늘색과 따뜻한 금색을 조금 섞는다. 겹치면 더 밝아지게 globalCompositeOperation 'lighter'로 그린다.
- 잔상: 매 프레임 화면을 완전히 지우지 않고 반투명 배경색으로 덮어, 움직일 때만 보이는 짧은 꼬리를 남긴다.
- 문장 모양: 화면 밖 캔버스에 굵은 한글 글꼴로 문장을 그리고, 글자 픽셀을 일정 간격으로 샘플링해 입자의 목표 위치로 쓴다. 글꼴은 'Malgun Gothic', 'Apple SD Gothic Neo', 'Noto Sans KR', sans-serif 순서로 쓰고 외부 글꼴을 불러오지 않는다.
- 문장이 길면 두 줄로 나누고, 화면 너비의 80% 안에 들어오게 글자 크기를 자동으로 줄인다.

## 3. 오프닝 (약 4초, 자동 재생)

- 0 - 0.6초: 완전한 어둠 가운데 작은 빛 하나가 깜빡인다.
- 0.6 - 1.6초: 빛이 터지며 모든 입자가 가운데에서 바깥으로 폭발하듯 퍼진다.
- 1.6 - 3.0초: 입자들이 은하처럼 소용돌이치며 돈다.
- 3.0 - 4.0초: 입자들이 제목 "별이 된 문장."으로 모여 자리 잡고, 부제와 조작 안내가 아래에서 떠오른다.
- 화면을 누르거나 키를 누르면 오프닝을 바로 끝낸다.

## 4. 조작

1. 다가가기: 마우스(휴대폰은 손가락)가 다가가면 반경 안의 별이 밀려나고, 멀어지면 스프링처럼 제자리로 돌아온다.
2. 누르기: 한 번 누르면 누른 자리에서 충격파가 퍼져 별이 크게 흩어졌다가, 1.2초 뒤 다음 문장으로 다시 모인다. 문장은 "별이 된 문장.", "오늘도 수고했어요.", 사용자가 넣은 문장 순서로 돈다.
3. 길게 누르기: 누르고 있는 동안 그 자리로 별이 빨려 들어가 밝게 뭉친다(블랙홀). 손을 떼면 초신성처럼 사방으로 터진 뒤 문장으로 돌아온다. 오래 누를수록 더 크게 터진다.
4. 내 문장 넣기: 화면 아래 입력창(최대 20자, 예시 문구 "예: 우리 팀 화이팅")과 "별로 만들기" 버튼. 누르거나 Enter를 치면 별이 그 문장으로 모인다.
5. 모양 바꾸기: 버튼 네 개 "문장", "하트", "은하", "불꽃". 하트와 은하는 수식으로 만든 목표 위치로 모이고, 불꽃은 목표 없이 위로 솟았다가 떨어지기를 반복한다.
6. 링크로 보내기: "링크 복사" 버튼은 주소 끝에 ?m=문장 을 붙여 복사한다. 이 주소로 열면 오프닝 마지막에 제목 대신 그 문장으로 모인다. 버튼 옆에 "링크에는 문장이 그대로 들어갑니다. 개인정보는 넣지 마세요." 한 줄을 작게 둔다.

모든 조작은 화면 위 HTML 버튼으로도 할 수 있어야 한다(키보드 Tab으로 이동 가능). 지금 화면의 문장은 화면에 보이지 않는 HTML 글자로도 넣어 화면 낭독기가 읽게 한다.

## 5. 움직임의 느낌

- 별은 목표 위치로 순간이동하지 않는다. 속도와 감쇠가 있는 스프링으로 움직여, 살짝 지나쳤다가 자리 잡는다.
- 별마다 반짝임 주기와 크기가 조금씩 다르다. 같은 문장이라도 살아 있는 별빛처럼 보여야 한다.
- 충격파와 초신성에는 화면이 잠깐 밝아지는 섬광(0.15초)을 함께 넣는다.

## 6. 꼭 지킬 것

- HTML/CSS/JavaScript만 사용하고, 지금 폴더의 index.html을 더블클릭하면 바로 열리게 한다. 인터넷 연결이 없어도 동작한다.
- 성능: 입자는 데스크톱 4,000개 안팎, 휴대폰(화면 너비 600px 이하) 1,800개 안팎. 기기 픽셀 비율은 최대 2로 제한한다. 탭이 숨겨지면 애니메이션을 멈춘다. 창 크기가 바뀌면 문장 위치를 다시 계산한다.
- 휴대폰(390px)에서 입력창과 버튼이 문장을 가리지 않는다. 버튼은 손가락으로 누르기 쉬운 크기(44px 이상)로 둔다.
- 동작 줄이기 설정(prefers-reduced-motion)에서는 오프닝, 잔상, 폭발을 끄고, 별이 문장 모양으로 놓인 정지 화면과 버튼 기능만 남긴다.
- 사용자가 넣은 문장을 HTML에 넣을 때는 textContent를 써서 코드로 해석되지 않게 한다.
- 섬광은 1초에 3번을 넘지 않는다.

## 7. 진행 방식

1. 만든 뒤 데스크톱(1440px)과 휴대폰(390px) 크기에서 오프닝, 다가가기, 누르기, 길게 누르기, 내 문장, 모양 4개, 링크 복사를 직접 확인한다.
2. 끊기거나 어색한 곳을 고친 다음, 무엇을 확인했는지 짧게 보고한다.
```

### 완성작 프롬프트: 심해 탐험
```text
# 스크롤로 내려가는 심해 탐험 - 연출 우선 프롬프트 (코드 그림판)

너는 과학관의 몰입형 전시를 만드는 인터랙티브 디자이너이자 프런트엔드 개발자다.
스크롤이 곧 잠수정의 하강이 되는 심해 다이브 사이트를 만들어라. 수면에서 시작해 해구 바닥 약 11,000m까지 내려간다.
제목은 "심해 탐험", 부제는 "스크롤을 내리면 잠수가 시작됩니다."

## 1. 사용자가 느껴야 할 것

- 열자마자 화면이 물속으로 뛰어든다. 3초 안에 "와" 하는 순간이 있다.
- 스크롤이 곧 잠수다. 빨리 내리면 기포와 해양설이 위로 세차게 흐르고, 멈추면 고요해진다.
- 1,000m 아래에서는 햇빛이 완전히 사라진다. 그 뒤로 보이는 것은 생물이 스스로 만든 빛과 내가 비추는 빛뿐이다.
- 어둠 속에서는 내가 직접 비추고, 음파를 보내고, 물을 휘저어야 무엇이 있는지 보인다.
- 맨 아래에서 잠깐 완전한 정적이 흐른 뒤, 수면으로 단숨에 올라가는 귀환으로 끝난다.

## 2. 그림: 이미지 없이 코드로 그린다

심해는 대부분 어둠이고, 보이는 것은 빛나는 점과 선이다. 그래서 사진보다 Canvas 2D로 그린 빛이 더 실제 같다.

- 사진, 이미지 파일, 외부 라이브러리를 쓰지 않는다.
- 수면 부근: 위에서 쏟아지는 빛줄기와 일렁이는 빛 무늬를 그라디언트와 노이즈로 그린다.
- 물빛: 수심에 따라 청록, 남색, 검정으로 이어지는 배경색. 1,000m를 넘으면 완전한 검정.
- 해양설: 크기와 속도가 다른 입자 세 겹(가까운 것은 크고 빠르게). 네모 대신 작은 원과 타원으로 그리고, 빨리 내려갈 때만 위로 길게 늘어난다.
- 생물은 어둠 속 실루엣으로 그린다. 스스로 빛나는 부분은 점, 선, 고리로 드러나고, 몸은 관측등이 닿는 곳에서만 보인다. 전체를 환하게 밝히지 않는다.
  - 샛비늘치 무리: 배 쪽에 줄지은 청록 점들이 떼 지어 움직인다.
  - 아톨라해파리: 붉은 원반 둘레를 파란 빛이 바퀴처럼 돈다.
  - 관해파리: 길게 이어진 빛 구슬 사슬이 천천히 물결친다.
  - 초롱아귀: 어둠 속 작은 미끼 빛 하나. 가까이 비추면 그 뒤로 거대한 입의 윤곽이 드러난다. 이빨은 밑동이 좁고 끝이 긴 바늘 모양이다. 길이, 간격, 안쪽으로 휘는 정도가 조금씩 다르며, 큰 이빨과 작은 이빨을 규칙적으로 번갈아 놓지 않는다. 이빨이 입 밖으로 삐져나오지 않게 자른다. 입 테두리와 눈은 희미하게 남긴다.
  - 덤보문어: 관측등 안에서만 살구색과 탁한 분홍빛 몸이 보인다. 정면의 동그란 얼굴 대신 비스듬히 기울어진 길쭉한 몸통을 그리고, 작은 눈 하나만 드러낸다. 빛을 받는 쪽은 밝고 반대쪽과 팔 아래는 어둡다. 얇은 지느러미 두 장은 서로 조금 다른 박자로 움직인다. 팔 사이의 막은 비대칭으로 접히고, 앞쪽 팔 몇 개만 가는 곡선으로 보인다. 점 눈 두 개와 똑같은 치마 주름이 있는 캐릭터처럼 그리지 않는다.
- 관측등: 가운데부터 가장자리까지 부드럽게 어두워진다. 옅은 푸른 물안개를 생물 뒤에 깔고, 몸 위를 하얗게 덮지 않는다. 빛 바깥에는 어둠을 충분히 남긴다.
- 빛은 globalCompositeOperation 'lighter'와 겹쳐 그린 반투명 원으로 번지게 한다.

## 3. 오프닝 (약 4초, 자동 재생)

- 0 - 1초: 수면 위 새벽 하늘과 잔잔한 수평선. 제목이 떠 있다.
- 1 - 2초: 카메라가 수면을 뚫고 들어간다. 화면이 짧게 흔들리며 하얀 물보라와 기포가 화면을 가득 채운다.
- 2 - 4초: 기포가 위로 빠져나가며 빛줄기가 쏟아지는 푸른 바닷속이 열린다. 부제와 "스크롤로 잠수 시작" 안내가 나타난다.
- 스크롤하거나 누르면 오프닝을 바로 끝낸다.

## 4. 하강과 장면

페이지 전체 스크롤을 수심 0 - 11,000m에 대응시킨다. 아래로 갈수록 같은 스크롤에 더 많은 수심이 내려가, 깊어질수록 빨라지는 느낌을 준다.
화면은 하나에 고정하고, 수심에 따라 배경과 장면이 바뀐다.
오른쪽에 잠수정 계기판을 고정한다: 수심(m), 수압(1 + 수심/10, 단위는 기압, 앞에 "약"), 남은 햇빛(%), 지금 층 이름.
빠르게 스크롤하면 계기판 숫자가 빠르게 돌고 화면 가장자리에 속도선이 생긴다.

층 이름과 경계는 일반적인 해양 층 구분만 쓴다: 햇빛층 0 - 200m, 박명층 200 - 1,000m, 자정층 1,000 - 4,000m, 심해저층 4,000 - 6,000m, 초심해층 6,000m 아래.

1. 햇빛층: 빛줄기와 빛 무늬. 화면을 누르면 그 자리에서 물결이 퍼지고 작은 물고기 떼가 흩어진다.
2. 박명층: 빛이 점점 줄어든다. 샛비늘치 무리가 지나간다. 1,000m에 닿는 순간 마지막 햇빛이 꺼지며 화면이 1초 동안 완전한 검정이 되고, "여기부터 햇빛은 닿지 않습니다." 한 줄이 떠오른다.
3. 자정층: 이때부터 마우스(휴대폰은 손가락) 주변만 관측등처럼 둥글게 밝다.
   - 마우스를 빠르게 움직이면 지나간 자리에 푸른 생물 발광이 번졌다가 사라진다.
   - "소나" 버튼이나 스페이스 키: 화면 가운데에서 둥근 음파가 퍼지고, 음파가 지나간 자리의 숨은 생물 윤곽이 1.5초 동안 초록 선으로 드러난다.
   - 아톨라해파리를 누르면 파란 빛 고리가 돈다. 관해파리 사슬이 화면을 가로지른다.
   - 초롱아귀: 미끼 빛 하나만 보인다. 관측등을 미끼에 가까이 대면 화면이 0.2초 번쩍이며 거대한 입의 윤곽이 드러났다가 어둠 속으로 물러난다. 소리 없이도 깜짝 놀라는 순간이어야 한다.
4. 심해저층: 진흙 바닥의 윤곽이 지나가고, 덤보문어가 관측등 빛 안에서만 천천히 떠 있다. 몸은 작게 기울고, 지느러미와 팔 끝이 서로 다른 속도로 움직인다. 빛을 옮기면 다시 어둠에 묻힌다.
5. 초심해층: 양쪽 벽이 좁아지는 해구의 윤곽. 바닥(약 11,000m)에 닿으면 계기판이 멈추고 모든 움직임이 2초 동안 멈춘다. 그다음 "가장 깊은 곳에 닿았습니다."와 "수면으로 돌아가기" 버튼이 나타난다.
6. 귀환: 버튼을 누르면 약 3초 동안 수심 숫자가 거꾸로 빠르게 줄고, 기포와 빛이 위로 쏟아지며 수면을 뚫고 나와 처음 화면으로 돌아간다.

장면마다 짧은 설명 두 문장을 화면 왼쪽 아래에 HTML 글자로 보여 준다. 생물 설명은 이름과 특징 한 줄만 쓰고, 확실하지 않은 숫자(크기, 서식 깊이)는 쓰지 않는다. 화면 속 생물 위치는 연출이며 실제 서식 깊이와 다를 수 있다고 마지막 화면에 밝힌다.
```

## 07 hyperframes로 모션 영상 만들기

### 영상 제작 준비물 확인과 설치 부탁
```text
내 PC에서 hyperframes로 영상을 만들 준비가 됐는지 확인해줘.
1) Node.js 22 이상, FFmpeg 가 설치돼 있는지 버전까지 확인
2) 없거나 버전이 낮으면 내 운영체제(Windows 또는 Mac)에 맞는 설치 방법을 알려주고, 내가 허락하면 설치까지 진행
3) 설치 후 새 터미널에서도 두 명령이 잘 잡히는지(PATH) 확인하고, 마지막에 npx hyperframes doctor 결과를 쉬운 말로 설명
설치는 한 단계씩 진행하고, 명령을 실행하기 전에 무엇을 하는 명령인지 먼저 말해줘.
```

```text
- 핵심 장면 3개 (각 2~3초): [장면 1, 예: 첫날 일정], [장면 2, 예: 자주 찾는 서식], [장면 3, 예: 물어볼 곳]
- 마지막에 사이트 주소 [내 주소]
- 분위기: [예: 차분하고 믿음직하게]
- 화면은 가로 16:9
영상 작업 파일은 내 사이트 폴더 바로 옆에 my-video 폴더를 새로 만들어서 거기서 작업해줘. 사이트 폴더 안에는 만들지 마.
```

### 렌더한 영상을 사이트 첫 화면에 넣기
```text
my-video/renders 폴더의 [파일 이름].mp4 영상을 내 사이트 첫 화면에 넣어줘.
- 영상 파일은 내 사이트 폴더의 assets/video/ 안에 intro.mp4 라는 이름으로 복사
- video 태그에 autoplay muted loop playsinline 을 모두 넣어서, 소리 없이 자동으로 반복 재생되게 해줘
- 영상이 로딩되기 전에 보일 대표 이미지(poster)도 영상 첫 장면으로 한 장 만들어서 같이 넣어줘
- 파일 크기를 가능하면 5MB 이하, 최대 10MB 이하로 줄여줘. FFmpeg로 해상도와 화질을 낮춰도 되는데, 줄이기 전과 후의 크기를 알려줘
- 휴대폰 화면 폭에서도 영상이 잘리지 않게 확인해줘
- 운영체제의 "움직임 줄이기" 설정을 켠 사람에게는 자동 재생을 끄고 재생 버튼을 보여줘
끝나면 내가 확인할 방법을 알려줘.
```

```text
출장비 계산기를 만들어 주세요. 한도와 단가는 제가 임의로 정한 예시 숫자입니다.
- 파일 하나(travel-calc.html), 더블클릭으로 열려야 합니다.
- 입력: 출장 일수, 교통비, 숙박비(1박당), 숙박 박수
- 일비는 하루 [예시 일비 숫자, 예: 30000]원으로 계산해서 더해 주세요. 이 숫자는 파일 맨 위에서 쉽게 바꿀 수 있게 해 주세요.
- 결과: 총 합계와 항목별 소계. 총 합계가 [예시 한도 숫자, 예: 500000]원을 넘으면 빨간 글씨로 "한도 초과"라고 보여 주세요.
- 숫자는 쉼표를 찍어 읽기 쉽게 보여 주고, 입력칸이 비어 있으면 0으로 보고 오류가 나지 않게 해 주세요.
- 만든 뒤 예시 3가지를 직접 계산해서, 화면의 결과가 맞는지 알려 주세요.
```

### 파일 정리 스크립트 (미리보기 먼저)
```text
파일 정리 자동화를 연습하고 싶어요. 실제 파일은 건드리지 않고, 연습 폴더 안에서만 진행합니다.
1. 이 폴더 안에 practice-files 폴더를 만들고 가짜 파일 20개를 만들어 주세요. 이름은 보고서1.pdf, 회의록 최종.docx, 사진_01.jpg처럼 제각각이고, 내용은 비어 있어도 됩니다.
2. 그 폴더의 파일을 확장자별 하위 폴더(문서, 이미지, 기타)로 나눠 옮기고, 이름 앞에 실행하는 날의 날짜(예: 20261006_)를 붙이는 스크립트를 만들어 주세요.
3. 스크립트를 처음 실행하면 "이렇게 바꿀 예정입니다"라는 목록만 보여 주고, 실제로는 아무것도 바꾸지 않게 해 주세요. 제가 확인용 옵션을 줄 때만 실제로 옮기게 해 주세요.
4. 파일을 삭제하는 동작은 절대 넣지 마세요. 같은 이름이 이미 있으면 덮어쓰지 말고 건너뛰고 알려 주세요.
5. 새 프로그램 설치 없이 이 PC에서 쓸 수 있는 방식으로 만들고, 미리보기용 실행 방법과 실제로 옮기는 실행 방법을 각각 한 줄로 알려 주세요.
6. 스크립트가 어떤 일을 하는지 초보자도 알 수 있게 쉬운 말로 설명해 주세요.
```

### 공지 메일 초안 만들기와 톤 비교
```text
아래 상황으로 사내 공지 메일 초안을 써 주세요. 실제 이름과 연락처는 쓰지 않고 [담당자 이름]처럼 자리 표시로 남겨 주세요.
상황: [예: 다음 주 금요일 오후 3시에 팀 교육이 있고, 장소는 3층 회의실이며, 노트북을 가져와야 합니다]
받는 사람: [예: 같은 팀 동료 10명]
요청:
1. 정중한 톤과 간결한 톤, 두 가지 버전으로 써 주세요.
2. 제목 후보를 3개 주세요.
3. 본문은 250자 이내로 하고, 날짜, 시간, 장소, 준비물이 한눈에 보이게 해 주세요.
4. 상황에 없는 내용(예: 점심 제공, 참석 필수 여부)은 지어내지 말고, 제가 정해야 하는 항목을 마지막에 질문으로 모아 주세요.
```

### 내 업무에서 AI에게 맡길 일 찾기
```text
저는 [내 직무]를 맡고 있고, 코딩 경험은 없습니다. 제가 하는 일 중에서 AI에게 맡기기 좋은 일을 함께 찾고 싶습니다.
1. 먼저 저에게 질문을 한 번에 하나씩, 최대 5개만 해 주세요. 매일이나 매주 반복하는 일, 시간이 오래 걸리는 일, 짜증 나는 일을 중심으로 물어봐 주세요.
2. 제가 답하면, 맡기기 좋은 일 3가지를 골라 이유와 함께 알려 주세요.
3. 고른 일마다 "가짜 예시 데이터로 먼저 연습하는 방법"을 알려 주세요.
주의: 저는 고객 이름, 개인정보, 사내 기밀은 말하지 않을 거예요. 그런 내용이 필요하면 예시로 바꿔서 알려 달라고 말해 주세요.
```

### 팀 공유용 5분 소개 자료 뼈대
```text
제가 AI로 해 본 일을 팀에 공유하려고 합니다. 5분짜리 소개 자료의 뼈대를 만들어 주세요.
- 한 일: [예: 가짜 데이터로 매출 대시보드 만들기]
- 걸린 시간: [예: 처음 20분, 수정 10분]
- 이전 방식과 비교: [예: 보통 1시간 걸림]
- 아쉬웠던 점: [예: 처음 그래프 색이 마음에 안 들어서 두 번 고침]
구성: 1) 무엇을 했나 2) 어떻게 부탁했나(프롬프트 한 줄 요약) 3) 결과 4) 조심할 점(개인정보, 인증정보, 회사 기밀을 넣지 않는다는 보안 수칙 포함) 5) 동료가 바로 따라 할 수 있는 한 가지 제안
회사 내부 정보와 실제 고객 정보는 들어가지 않게 해 주세요. 확실하지 않은 숫자는 [확인 필요]로 표시해 주세요.
```

### 내 사이트에 새 장면 추가 부탁
```text
지금 만들고 있는 사이트에 새 기능을 하나 추가하고 싶어요.
추가하고 싶은 것: [예: 스크롤을 끝까지 내리면 나타나는 "다음 이야기" 장면]
조건:
1. 기존 화면과 색, 글꼴, 분위기가 어울리게 해 주세요.
2. 휴대폰 화면에서도 깨지지 않게 해 주세요.
3. 바꿀 파일과 이유를 먼저 짧게 알려 주고 진행해 주세요.
4. 끝나면 제가 직접 눌러 보며 확인할 순서를 알려 주세요.
제가 확인하고 "올려 주세요"라고 말하면 그때 GitHub에 올려서 내 주소에 반영해 주세요. 그 전에는 올리지 마세요.
```

### 8장 완료 확인
```text
8장 업무 활용 연습이 제대로 되었는지 확인해줘. 파일은 아무것도 바꾸거나 올리지 말고 확인만 해줘.
1. 지금 열린 폴더가 연습 전용 폴더인지 (바탕화면이나 문서 폴더 전체가 아닌지)
2. 업무 활용 예시 하나 이상(CSV 정리, 대시보드, 회의록, 매뉴얼, 계산기, 파일 정리, 메일 초안 중)이 결과 파일까지 끝까지 만들어져 있고 열어 보면 정상인지
3. 이 폴더의 파일에 실제 개인정보(주민등록번호, 연락처, 주소, 이메일), 인증정보(비밀번호, API 키, 토큰), 회사 기밀로 보이는 내용이 없고 모두 가짜 예시 데이터인지
각 항목을 O 또는 X로 표로 정리해줘. X가 있으면 원인과 해결 방법을 알려주고, 모두 O이면 "완료"라고 답해줘.
```

## C Copilot만 있을 때: 설치 없이 만들고 배포하기

### Copilot: index.html 파일로 받기
```text
아래 요구사항으로 웹페이지를 만들어서 index.html 파일 하나로 다운로드 링크를 줘. 채팅 화면에 코드는 보여주지 마.
- CSS와 JavaScript는 모두 파일 안에 작성
- 외부 라이브러리, CDN, API 호출은 쓰지 마
- 한국어 화면, <meta charset="utf-8"> 포함, 휴대폰에서도 깨지지 않게
- 내용은 가짜 예시 데이터만 사용
- 앞으로 수정을 부탁하면 항상 전체 파일을 새로 만들어 다운로드 링크로 줘
요구사항: [만들고 싶은 것]
```

### Copilot: zip으로 다시 받기
```text
다운로드 링크가 열리지 않아. 같은 내용을 site.zip 파일로 압축해서 다운로드 링크를 다시 줘.
zip을 풀었을 때 index.html이 맨 위에 바로 보이게 해 줘.
```
