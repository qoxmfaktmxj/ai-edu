# ONE CUP - 한 잔이 되기까지.

스크롤로 핸드드립 한 잔의 과정(원두, 분쇄, 준비, 뜸들이기, 추출, 완성)을 따라가는 예제입니다.
순수 HTML/CSS/JS(ES 모듈), 빌드 과정 없음. 진입 경로: `/examples/coffee/`

## 파일

```
coffee/
  index.html      여섯 단계 글, 단계 바로가기, 장면 SVG(원두, 그라인더, 필터, 드리퍼, 주전자, 투명 컵)
  styles.css      색과 글꼴 토큰(:root), 데스크톱 2단/모바일 상단 고정 장면 배치
  js/data.js      STEPS(단계 이름과 진행률 구간), T(장면 안의 세부 타이밍), CUP_FILL(완성 액면 78%)
  js/scene.js     renderCoffee(progress): 진행률 하나에서 모든 도형의 위치와 상태를 직접 계산
  js/app.js       스크롤을 진행률로 바꾸고, 바로가기와 "처음부터 다시"를 같은 기준으로 이동
  assets/fonts/   Pretendard 서브셋(이 페이지 글자만, SIL OFL 1.1)
```

## 고치는 위치

- 단계 이름, 진행률 구간: `js/data.js` 의 `STEPS`. 세부 타이밍(붓기 두 번, 방울 구간, 드리퍼 옮기기 등): 같은 파일의 `T`.
- 화면 문구: `index.html` 의 각 `<section class="step">`. 정보 패널 문구는 마지막 section의 `<details>`.
- 색: `styles.css` 의 `:root` 토큰. 그림 속 색은 `index.html` SVG의 fill/stroke(원두 `beanFill`, 주전자 `copper`, 그라인더 `wood`).
- 글자를 바꾸면 글꼴 서브셋을 다시 만듭니다(방법은 `../deep-sea/README.md` 참고).

## 동작 기준

- 진행률은 각 실제 섹션의 스크롤 구간을 그 단계의 구간에 연결합니다. 단계 글이 제자리에 고정되는 순간이 그 단계의 시작이라, 글을 읽는 동안 다음 단계 그림이 나오지 않습니다. JS가 있으면 현재 단계의 글만 보입니다.
- 같은 진행률이면 같은 화면입니다. setInterval이나 누적 카운터가 없고, 스크롤을 멈추면 방울과 액면도 멈춥니다.
- 물줄기는 매 프레임 주전자 회전 각도로 계산한 주둥이 끝에서 시작해 드리퍼 안 커피(또는 고인 물) 표면에서 끝납니다. 붓기가 끝나면 꼬리가 표면으로 떨어지므로 공중에 남지 않습니다.
- 방울은 드리퍼 출구에서 현재 액면까지만 움직이고 액면에서 작은 물결이 됩니다. 마지막 방울(진행률 0.885) 뒤에 드리퍼를 옆 접시로 옮깁니다.
- 그리는 순서: 컵 뒤 윤곽 > 액체 > 방울 > 컵 앞 윤곽과 반사광 / 드리퍼 뒤 면과 필터 > 커피층과 고인 물(필터 마스크) > 물줄기 > 드리퍼 앞 면. 드리퍼 안쪽과 앞면은 같은 transform을 받아 함께 움직입니다.
- 모션 감소: 원두 회전, 크랭크 회전, 분쇄 입자, 방울 이동, 증기 흐름을 생략하고 각 단계의 대표 상태와 설명, 바로가기는 유지합니다. 부드러운 스크롤도 끕니다.

## 네 스킬이 바꾼 것

- design-taste-frontend: 왼쪽 짧은 글(5) + 오른쪽 큰 장면(7)의 2단, 장면은 sticky로 고정. 원두에서 완성된 컵까지 같은 탁자 선 위에서 시선이 이어지게 구성. 모바일은 장면을 위에 고정하고(viewBox meet, 잘라내지 않음) 글을 아래에 둠.
- ui-ux-pro-max: 디자인 시스템 검색이 제안한 분홍 포인트 팔레트와 손글씨 글꼴은 주제와 맞지 않아 쓰지 않고, 한국어 단일 글꼴 조합(Korean Modern 계열)을 Pretendard로 적용. 브리프 색의 대비를 계산해 구리색 #C78550(크림 위 2.7:1)은 그림에만, 조작부 강조는 녹색 #536A5E(5.2:1), 본문은 #6B5A4E(5.8:1)로 정함.
- hyperframes(hyperframes-animation 규칙을 스크롤 진행률에 맞게 적용): nudge-curve(컵, 드리퍼, 필터가 느리게 출발해 빠르게 이동한 뒤 길게 감속하며 한 축에 정렬), control-target-sync(붓는 양 하나가 주전자 각도, 물줄기, 고인 물, 젖은 원두 색을 함께 움직임), 레이어 순서와 clipPath로 원두가 그라인더 입구 뒤로 가려지는 전환.
- impeccable(audit, craft-floor 점검 후 수정):
  - 다음 단계 글이 이전 글, 바로가기 바와 겹쳐 보이던 문제: 현재 단계 글만 보이게 수정.
  - 주전자 목이 드리퍼 테두리를 가로지르던 문제: 붓는 동안 주전자를 들어 올리고 안쪽으로 당겨 물줄기를 수직으로 만듦.
  - 바로가기 터치 영역 40px을 44px로 늘림. 제목 위 단계 번호와 브랜드 라벨(eyebrow)은 빼고 진행은 바로가기의 현재 표시로 보여 줌.
  - 키보드 바로가기로 이동한 뒤 포커스가 사라지던 두 단계(추출, 완성)에 tabindex 추가.
  - 텍스트 선택 색을 팔레트로 지정.
  - 검사기 경고 두 가지는 브리프 지정 사항이라 유지: 크림 배경(#F7F0E4 지정), SVG 직접 그림(사진/생성 이미지 대신 SVG로 그리라는 요구).

## 배포

교육 사이트(Next.js)의 `public/examples/coffee/` 로 함께 배포됩니다. 프로젝트 빌드 설정은 바꾸지 않았고, `next.config.ts` 의 examples 전용 리다이렉트(`/examples/:name` -> `/examples/:name/index.html`)로 상대 경로가 풀립니다.
이 폴더만 독립 배포할 때는 Vercel Root Directory를 이 폴더로, Framework Preset `Other`, Build Command 빈값(Override), Output Directory `.`(Override)로 설정하고 `/` 로 엽니다.

## 확인한 것 (로컬 Next dev 서버, Chromium 헤드리스)

- 1440x900, 390x844(터치), 모션 감소에서 진행률 0 -> 1 순서대로 여섯 단계와 바로가기 현재 표시가 맞음
- 0.8 -> 0.3 -> 0.55 -> 0.8 역방향 이동 뒤 같은 상태, 0.66에서 새로고침 뒤 액면 같음
- 키보드로 바로가기(추출) 이동 시 해당 단계로 스크롤과 포커스 이동, "처음부터 다시"는 맨 위와 첫 단계로 포커스
- 모바일에서 주전자 끝, 드리퍼, 컵이 모두 보임
- 콘솔 오류 없음, 404 없음

실제 Vercel Preview URL에서의 확인은 하지 않았습니다(main 푸시 후 자동 배포).
